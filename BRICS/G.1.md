# BRICS/G.1 — Opening round: entry-point nodes for Brazil, Russia, China, India, 2026-08-13

## Orientation

Direct continuation of AF/G.24, opened by Thomas's instruction "chase your leads down and then we can move on to brics." This is the first BRICS-branch round. Per `cleanup-2026-08-13-and-brics-scoping.md`'s own scoping notes, Brazil already had a small foothold (`br-fpm-population.json`, `br-fiscal-responsibility-law.json` — the FPM transfer-formula chain and the LRF/RREO/RGF transparency-reporting chain), while Russia, China and India were fully greenfield — zero prior corpus presence. This round dispatched 4 parallel research agents (one per country) to find each country's two standard branch-opening building blocks, matching the pattern every other branch in this corpus opened with: (1) the primary official consumer price index, and (2) a core intergovernmental fiscal-transfer mechanism. For Brazil specifically, the research targeted the two items its own existing files had explicitly deferred as "the obvious next Brazilian pass" — the IPCA/INPC CPI chain and the state-level FPE (Fundo de Participação dos Estados), the sibling of the already-documented municipal-level FPM. Research findings were then synthesized by 4 parallel synthesis agents into new corpus files, following the exact same evidence-only schema and discipline as every other branch (AF, EU, US, AU, NZ) in this project.

## Session conditions

Same evidence-strict standing rule as every other branch: verbatim quote + exact URL from a primary, government/agency-authored document for every claim; NOT FOUND is a legitimate, valuable outcome, recorded honestly in `_dropped` rather than left unmentioned. Both this round's research and synthesis agents were briefed on a live methodological lesson carried forward from AF/G.24: an AI web-fetch tool has been known to fabricate plausible-looking fake content for a dead/unreachable URL instead of reporting the failure — always raw-verify a URL is genuinely live before trusting extracted text from it. Every research agent this round independently reported doing exactly this kind of raw-verification when a fetch tool's own summarized output was in doubt (see Findings below), and none accepted a proxy- or browser-rendered page's content without first confirming the underlying HTTP response was genuine.

Three sibling agents made this same palette edit independently in parallel without conflict — verified afterward that all three landed cleanly.

Every country's opening round surfaced at least one real, load-bearing access failure alongside real content — most strikingly Russia, whose primary statistics agency (Rosstat: `rosstat.gov.ru`, `gks.ru`, `fedstat.ru`) was completely unreachable by any method tried this round, forcing that branch's CPI building-block to be sourced instead to the Bank of Russia's own monetary-policy document (which names Rosstat's CPI by abbreviation without being Rosstat's own text) — a legitimate, evidence-disciplined substitution, not a shortcut. China and India both minted rich content but drew **zero dependency edges** this round — in China's case because every candidate edge (the 1994 tax-sharing decision, the equalization-formula document) hit a genuine access wall; in India's case because a synthesis agent explicitly drafted and then discarded an FC16→Article 280 edge for lacking a verbatim in-text citation, preferring an honest `deferred` note over a plausible-but-unsupported edge — exactly the discipline this corpus's evidence rule exists to enforce.

`npm run validate` and `npm run build` both pass clean: **1078 reports, 969 dependencies, all 44 logic checks pass, 221 slices, 0 unwired**, `tsc --noEmit && vite build` succeeds. All 5 new/modified files (4 corpus JSON + `palette.ts`) were pushed to the device via `SendUserFile` + `device_commit_files`; **nothing from this round is git-committed yet**, per the project's standing rule (carried over from the AF branch, applies project-wide).

## Findings

### 1. Brazil — IPCA/INPC minted, FPE's constitutional basis corrected, a live IPCA-indexing edge found back to the existing FPM chain

Minted 6 nodes in `br-ipca-fpe.json`: `br-ipca` and `br-inpc` (IBGE's two consumer price indices — IPCA covers 1–40 minimum-wage households from any income source, ~90% urban coverage, the Banco Central's inflation-target index since July 1999; INPC covers only salaried 1–5 minimum-wage households, ~50% coverage, aimed at wage-purchasing-power correction — both verified directly from IBGE's own product pages), `br-decreto-12079-2024` and `br-resolucao-cmn-5141` (the real citation chain: the presidential decree establishing inflation-targeting delegates the specific index choice to the Conselho Monetário Nacional, whose own Resolução 5.141/2024 is the actual instrument naming IPCA by name), `br-fpe-dn-tcu` (the state-level sibling of the existing FPM mechanism — TCU's annual Decisão Normativa fixing each state's Fundo de Participação dos Estados coefficient, with real per-state figures quoted from two consecutive editions), and `br-lc-62-1989` (the statute defining FPE's population-plus-inverse-per-capita-income formula). Six edges, including two genuine cross-file edges into the pre-existing `br-fpm-population.json` (FPE's own TCU instrument cites IBGE's population estimates and Lei 8.443 the same way FPM's does), and one that connects this round's two topics directly: `br-lc-62-1989 -[calculated_from]-> br-ipca`, since the FPE baseline amount is itself IPCA-indexed by the statute's own text. A real error in the original research brief's hypothesis was caught and corrected during research: FPE is Article 159, I, alínea "a" (a sibling of FPM's alínea "b" under the same inciso), not a separate Article 159, II as originally guessed — recorded explicitly as a `_dropped` note rather than silently fixed.

### 2. Russia — opening round for a new branch; Rosstat itself unreachable, but a real equalization-grant chain built from the Ministry of Finance's own site

Minted 4 nodes in `ru-cpi-equalization.json`: `ru-cbr-monetary-policy-guidelines` (the Bank of Russia's own current Monetary Policy Guidelines document, naming Rosstat's ИПЦ as the ~4% inflation-target measure — this stands in for a Rosstat-sourced CPI node, since Rosstat's own site was completely unreachable this round), `ru-budget-code-art131` (the Budget Code's equalization-grant statute, sourced to a third-party legal-database mirror since no working .gov.ru host was found — flagged explicitly as third-party-hosted, following this corpus's standing convention for such sourcing), `ru-resolution-670-equalization-methodology` (the Government Resolution the Budget Code delegates the actual formula to — its existence, number and amendment history confirmed, but its operative formula text itself unverified/paywalled), and `ru-minfin-2026-equalization` (the branch's strongest node — a genuinely `minfin.gov.ru`-hosted 2026 per-region "budgetary sufficiency" index table, Russia's direct structural analogue to Brazil's per-capita FPE coefficients). Two edges, both deliberately conservative `cites` relationships rather than a stronger type the evidence didn't fully support. Rosstat's total unreachability (rosstat.gov.ru, gks.ru, fedstat.ru all failed by TLS reset, 503, or 403 respectively) is recorded as this branch's headline access gap — a genuine, structural finding for a future round to retry with different network tooling, not a research shortcut.

### 3. China — opening round for a new branch; real CPI and transfer-budget content minted, but every candidate edge hit a genuine access wall

Minted 3 nodes in `cn-cpi-transfers.json`: `cn-nbs-cpi` (NBS's monthly CPI release, with its full 8-category/268-classification basket methodology, sampling method — ~120,000 price-survey points across 31 provinces — and the 2025 base-period rebasing, all quoted verbatim with English glosses), `cn-npc-government-work-report` (the State Council's 2026 Government Work Report, whose ~2% CPI target is explicitly tied to monetary policy in its own text), and `cn-npc-budget-report` (the Ministry of Finance's annual Budget Report to the NPC, with real 2026 planned and 2025 actual transfer-payment figures — RMB 10.415 trillion total central-to-local transfers, RMB 2.834 trillion of that specifically equalization transfers — and its own citation to the Budget Law). Zero edges: the two most likely dependency targets — the 1994 tax-sharing foundational decision and the Ministry of Finance's own equalization-transfer formula measures document — were both genuinely inaccessible (the former only as an un-OCR'd scanned PDF, the latter blocked by a reproducible 502/403 on the Ministry's own subdomain), and the Budget Report's own text does not cite either by name, nor does the Government Work Report ever name the National Bureau of Statistics despite using its CPI figures — all four of these are recorded as explicit `_dropped` findings rather than assumed.

### 4. India — opening round for a new branch, unusually rich: two full Finance Commission reports with real weighted-criteria formulas

Minted 5 nodes in `in-cpi-finance-commission.json`: `in-mospi-cpi` (MoSPI/NSO's CPI, freshly rebased to 2024=100 from 2012=100, COICOP-2018-aligned, with the July 2026 release's real methodology and cadence detail), `in-rbi-act-45za` (the RBI Act's statutory inflation-targeting mechanism — deliberately scoped to only what Section 45ZA's own text establishes, the process of determining and gazetting a target, since this round could not verify the actual notified "4%"/"CPI (Combined)" language behind an RBI bot-wall and a CAPTCHA-gated gazette search), `in-constitution-art280` (the constitutional basis for India's Finance Commission), and both `in-fc16-report` and `in-fc15-report` (the Sixteenth and Fifteenth Finance Commissions' own reports, each with a verbatim weighted-criteria horizontal-devolution formula table — FC16: Population 17.5% / Demographic Performance 10% / Area 10% / Forest 10% / Per Capita GSDP Distance 42.5% / Contribution to GDP 10%; FC15: Population 15% / Area 15% / Forest and ecology 10% / Income distance 45% / Tax and fiscal efforts 2.5% / Demographic performance 12.5% — both retaining the same 41% vertical-devolution share). Zero edges: a synthesis agent explicitly drafted and then discarded an FC16→Article 280 `cites` edge, since no verbatim passage in FC16's own text cites Article 280 by number (unlike this corpus's existing precedent for that edge shape, which requires the dependent document's own citation line) — recorded as a `deferred` lead instead of an unsupported edge. FC16's own explicit citation of Census of India 2011 (not MoSPI) as its population-data source, and its total silence on CPI/inflation data despite citing MoSPI repeatedly for GDP/GSDP, are both recorded as genuine findings.

## Secondary observations

* **Every research agent this round independently practiced the WebFetch-hallucination-avoidance discipline flagged at AF/G.24**, without being told the specific mechanics — raw-`curl`-verifying HTTP status codes before trusting extracted content, distinguishing a genuine 502/403 from a JS-rendering failure, and refusing to accept CAPTCHA-gated or bot-walled content by any workaround. This is a good sign the lesson generalizes past the branch it was discovered in.
* **China and India both minted real content but zero edges this round — this is a legitimate branch-opening shape, not a research shortfall.** A brand-new branch's first-round nodes are often standalone reference documents (a CPI release, a constitutional article, a standing report) with no yet-discovered textual citation to another node in the same small file — the same pattern AF/G.17's own opening 21-file population push showed for several countries before later rounds found connecting edges. Future BRICS rounds should expect the edge count to grow as more of each country's corpus is built out, not expect every opening node to already connect to something.
* **The palette.ts sanctioned-edit pattern held up under concurrent parallel edits.** Three synthesis agents (Russia, China, India) each independently needed to add a `COUNTRY_FAMILY` entry to the same file in the same parallel dispatch — all three landed without conflict or clobbering, confirmed by inspection afterward. Worth remembering this is a genuine (if narrow) exception to "don't hand-edit generated/shared files" — `palette.ts` is not auto-generated and is explicitly meant to be touched when a new country is added, per its own sibling file's code comment.

## How to write the next hand-off

(Copied verbatim per project convention, same spec block used by every branch in this corpus.)

Required sections, in this order: Orientation, Session conditions, Headline result, Findings (numbered `###` subsections, one per country/topic), Secondary observations, Corrections to prior sessions (never omit this section — even "none this session" is itself a claim, state it explicitly), Thomas's stated priority for the remaining work, Cheap checks still outstanding, What to pass at the start of next thread, and this spec block itself, copied verbatim into every hand-off.

Never edit a predecessor file. Corrections to earlier sessions go in the new file's Corrections section, dated and attributable to this session.

Every claim needs a document behind it — a URL/location and, wherever practical, a verbatim quote. "Comparable with"-type language is not a dependency. Tense matters: a PAST-tense arrangement is not a live dependency; flag it if a source's tense is ambiguous. AGENCY ONLY and NOT FOUND are legitimate research outcomes, not failures — record them in `_dropped` with an honest reason, don't leave the question unanswered and don't force an edge that isn't there.
