# V0.8 — A prioritisation that became an audit, and a constant that paid for vagueness
Session date: 2026-07-29
Supersedes V0.7. Counts are **unchanged at 121 reports / 195 dependencies** — but
**the authority ranking changed for the first time since V0.4**, and that is the
headline. The Census is no longer the top-ranked node.

The session ran in two halves. The first prioritised the backlog and turned into an
audit; the second implemented three of the four things the audit found. **Two
items are decided and deliberately not built** (the `determination` field, the
disclosure ratio in the hover card) and are marked as such throughout.

`npm run logs` says the next log is V0.9 and no rollup rides with it; the next
rollup is due with V0.10.

## The theme: the documents had drifted from the data

V0.7's theme was four features that had never worked. This one's is adjacent:
**four claims that were true when written and are not true now**, plus one that was
never true. None was a mistake at the time. They rotted because nothing reads a
document and checks it against the graph.

The prioritisation was the trigger. Ranking twelve expansion clusters meant
measuring what the graph actually contains, and the measurements disagreed with the
documents four times.

Method worth recording: rather than run `npm run validate`, the loader
(`index.ts`) and the authority calculation (`graph.ts`) were **reimplemented from
scratch in Python** and checked against V0.7's recorded verification. They agree on
every overlapping figure — 121/195, six duplicate edges, the LGFF orphan, and the
top six authority scores to three decimals. That agreement is what makes the rest
of the numbers here trustworthy, and it is a cheap technique worth reusing: an
independent implementation catches things a validator written by the same hand as
the loader cannot.

*(Incidental: `npm run validate` cannot run in a Linux sandbox at all, because
`node_modules` holds Windows `esbuild` binaries. Reinstalling would have broken the
local Windows setup, so it was left alone. Any future sandboxed session needs a
copy outside the project folder.)*

## The finding that matters: authority peaks at exactly one disclosed input

This came out of a question about how to visualise undocumented influence, and it
is the most consequential thing in this log. It is **not a bug** — it is
`SELF_RETENTION = 1.0` doing exactly what it says, with a consequence nobody had
traced.

A node keeps `retention / (retention + total outgoing weight)` of its own rank.
Retention is fixed at 1.0. Outgoing weight is not. So **how much of its own
authority a node keeps is set by how many inputs it discloses, and how strongly.**

| Outgoing edges | Total weight | Keeps |
|---|---|---|
| none | 0 | 0% — mass goes to the dangling pool, spread evenly |
| one `cites` | 0.25 | **80%** |
| one `methodology_depends_on` | 0.50 | **67%** |
| one `uses_data_from` | 0.80 | 56% |
| one `calculated_from` | 1.00 | 50% |
| three, a well-documented node | ~2.30 | **30%** |

Measured on the Alberta Economic Outlook, disclosing inputs one at a time:

```
0 inputs   0.1647
1 input    0.3028   +0.1381   <- gains retention
2 inputs   0.2358   -0.0670
3 inputs   0.2141   -0.0217
4 inputs   0.2025   -0.0115
5 inputs   0.1953   -0.0072
```

**The peak is at exactly one**, and describing that one input honestly costs you:
as `cites` it scores **0.515**, as `calculated_from` **0.277**. The vaguest
available characterisation is worth 1.9× the most precise one.

### It reaches the current top four

| Rank | Node | In-degree | Out-degree | Keeps |
|---|---|---|---|---|
| 1 | Census of Population | 5 | 1 (`methodology_depends_on`) | **66.7%** |
| 2 | StatCan CPI | **13** | 3 | **30.3%** |
| 3 | SEPH | 3 | 1 (`methodology_depends_on`) | **66.7%** |
| 4 | Regulated Property Assessment Guidelines | 2 | 1 (`methodology_depends_on`) | **66.7%** |

The Census outranks the CPI on **five incoming edges against thirteen**. The
difference is not that the Census is more foundational — it is that the Census
discloses one input weakly and the CPI honestly documents three.

### What this does and does not cost the flagship result

V1.5 records that "both scoring methods independently put consumer price
measurement and population counting at the foundation of both national systems…
without anything being tuned to produce it."

**The first half stands.** Both methods do put those two at the top, and that was
not tuned for. **The ordering between them cannot be claimed.** Raw in-degree puts
the CPI first by a wide margin; weighted authority puts the Census first; and the
mechanism for the disagreement is a constant, not the data. REPORTS.md's own
cross-check — "if the two rankings disagree wildly that usually means the edge data
is wrong" — is what caught it, and this time the edge data is fine.

### It is the sink-leak bug's descendant

Retention was introduced because full transfer let a node with one outgoing edge
drain everything into its single target. That is the **receiving** side, and it was
fixed. The **transmitting** side was not: having exactly one outgoing edge is now
the optimal position for a node's own score.

V1.5's stated reason for retention is that "out-degree in this graph is a fact
about our research, not about the world." A *fixed* retention competing against
*variable* outgoing weight reintroduces precisely that dependency in a new shape.
The principle was right and the implementation only half-honoured it.

### The fix, chosen and shipped

`retention = α × total outgoing weight`, so every node keeps a constant
`α / (1 + α)`. At α = 1.0: all four relationship types converge on an identical
0.212 for the test node, and the curve flattens to
`0.145 → 0.212 → 0.230 → 0.237 → 0.241 → 0.242` — rising and plateauing instead of
peaking and falling.

Four options were put to the human, because the choice turns on whether to overturn
the project's most-quoted finding rather than on anything technical. **Proportional
retention was chosen.** The three rejected: display out-degree beside authority and
leave the maths alone (preserves a known artifact), fix only the zero-to-one-edge
cliff (leaves the one-edge optimum), and demote the ranking to a size encoding only
(concedes more than the evidence requires).

**What it cost.** The top is now CPI 1.000, US CPI 0.730, Census 0.679. The Census
dropped from first to third and four sessions of ranking stability ended. Two
consolations, both real:

- **The two rankings now agree at the top.** Weighted authority and raw in-degree
  both put the Canadian CPI first and the US CPI second. They disagreed before.
  Given REPORTS.md treats that disagreement as the signal that something is wrong,
  agreement is the outcome the cross-check was built to produce.
- **Node size barely moved** — top-to-median radius 2.07× against 2.14× before,
  4.3× against 4.6× in area. The legibility findings from V0.5 are unaffected.

V1.5's flagship claim now needs splitting in half. Both scoring methods still
independently put consumer price measurement and population counting at the
foundation of both national systems, and nothing was tuned to produce that. The
*ordering* between them was an artifact of the constant.

One discontinuity is accepted rather than papered over: a node with no outgoing
edges gets no retention, because retention is now a multiple of a weight it does
not have. Giving true sinks a self-loop lets them hoard, which is the original
sink-leak bug made worse.

## Four documented claims that were stale

**The Survey of Household Spending edge already exists.** `BACKLOG.md` called it
"the most obvious missing edge in the entire graph" and V0.7's recommended next
steps listed it as a cheap win. Both wrong. `statcan-shs` is a node with three
edges, and it was built *better* than either document proposed: the primary is
`statcan-cpi -> statcan-hfce` (`calculated_from`) with SHS as a `uses_data_from`
supplement, which is what the 2026 basket-update paper actually says. The
"mirrors the US CE Survey" framing asserted a parallel Canada does not have — the
US CPI *is* `calculated_from` the CE Survey; the Canadian CPI reweights from HFCE.

**The Equalization node already exists**, as a single-edge leaf pointing at
`statcan-population-estimates`. Building its Representative Tax System edges is
therefore small work on an existing node, not a new cluster — and it converts the
hub that all interprovincial work would attach to from a leaf into a hub.

**The banking island is closed.** Six `_dropped` notes across four slices record
that nothing connected the banking cluster to the rest of the graph. It has since
been bridged; the graph is one component even over documented edges alone. The
notes were never updated.

**`_dropped` holds 61 entries, not the ~55 estimated**, and one is a live
contradiction: `bea-gdp -> bea-pce` **exists as a documented edge with no
`evidence_url`** while a `_dropped` note rejects it on the grounds that no BEA
document states it as a source-data relationship. The corpus asserts both.

**The common cause: `_dropped` entries were never removed when the edge was later
built.** Two documents recommended finished work off stale notes. The block was
write-only — things went in and nothing read them again.

### `_dropped` is now data, and it was worth more than expected

All 61 entries were read, classified and restructured. Each now carries `source`,
`target` and `reason` alongside the original `edge` string and the untouched `why`
prose, typed as `DroppedNote` and exported from the loader as `droppedNotes`.

The reason vocabulary separates **answers** from **leads**, which is the
distinction the block was failing to make:

```
 15  no-document            searched; nothing states it
 11  unpublishable-source   real input, not a published release — FR 2644, W-2 records
 10  denied                 a document explicitly says it does not hold
  6  no-node-yet            documented; an endpoint has not been researched   <- LEAD
  6  deferred               deliberately out of a slice's scope, described as real <- LEAD
  5  wrong-target           real dependency, different release
  3  note                   an observation about the corpus, not a dropped edge
  2  wrong-direction        real relationship, running the other way
  1  unreadable-source      published but not machine-readable — the Issuu case
```

**12 of 59 are research leads**, which is the research backlog made countable for
the first time. Several are strong: `bea-pce -> uscensus-retail-and-services-surveys`
("better documented than most edges in this file"), the Fed's own Basel framework
page, the Grande Prairie requisitions named in the bylaw with dollar figures.

Method note worth keeping: the classification was applied through a script with an
explicit `(file, index) -> (source, target, reason)` mapping, and **the script
refused to run until every id resolved to a real node.** It caught nine ids that
had been assumed from the prose and were wrong — `ab-hshs-business-plan` against
the real `ahs-business-plan`, and eight entities that turn out not to be nodes at
all (`coicop`, `imf-sdds-plus`, `us-federal-minimum-wage`, `cpp-actuarial-report`
among them). Hand-editing fourteen files would have silently embedded all nine.

Two entries were deleted as superseded. `npm run validate` now fails loudly if any
note describes an edge that exists, so the specific failure that misled two
documents cannot recur silently.

The two banking-island notes were **corrected rather than deleted.** Their
structural claim is false — the graph is one component even over documented edges
alone — but the substantive observation survives and is still worth research: the
graph describes what banks charge and what capital banks must hold, with nothing
documented between the two. Being in one component is not the same as that seam
being described.

## The evidence standard is not being met, and only in the seed set

**27 of 187 documented edges carry no `evidence_url`. All 27 are seed edges. All
160 research-slice edges have one.**

The standard is enforced perfectly where research happens and not at all where the
graph started, which means the gap cannot close by accident — every future batch is
compliant and the hole stays exactly the same size.

Filtering to documented-plus-`evidence_url` only:

- The graph is **three components** (106 / 5 / 4), not one.
- **Six nodes drop out entirely**: the FOMC Statement, the Monetary Policy Report,
  the Summary of Economic Projections, H.15, PCE, and the CPP YMPE.
- The Bank of Canada rate corridor becomes a five-node island; the Social Security
  chain a four-node island.

The 21 that have no research replacement are concentrated in the monetary-policy
core, and the documents are not obscure. One URL — `boc-policy-rate -> statcan-cpi`
— reconnects the whole rate corridor.

**All six duplicate edges resolved to the seed copy, and in all six the losing
research copy had an `evidence_url` while the winning seed copy did not.** One pair
also disagreed on `relationship_type`, so the duplicate rule was affecting
authority and not just metadata.

**Fixed this session.** Later definition now wins for edges; first still wins for
reports, which remains a deliberate curation choice. Measured result matched the
prediction exactly: 3 of 117 rank positions moved, the top four were untouched,
`evidence_url` coverage went 160 → 166, the strict-standard split went from three
components to two, and orphans from six to two. No reference period was lost — the
paired values were identical wherever both copies carried one, which incidentally
corrects a claim in the old loader comment that three had vanished this way.

Two nodes still fall out entirely under the strict standard: `boc-mpr` and
`fed-h15`. The Bank of Canada rate corridor is still a five-node island, and one
URL on `boc-policy-rate -> statcan-cpi` would reconnect it.

## The single connected component is thin

Not previously measured. **40 of 187 documented edges are bridges** — removing any
one disconnects the graph — and **32 of 121 nodes are articulation points.** So
"one connected component" is true and oversells the structure: much of the
periphery is a tree hanging off a few hubs.

This became the ranking criterion. *Connectivity beats volume* was already
doctrine; the bridge fraction makes it checkable. **If a tier of work raises the
bridge fraction, it added territory rather than structure.**

## Decided this session

**Disclosure is a property of the source, not a gap in the research.** Recorded in
REPORTS.md, **not implemented.**

The evidence standard answers "does a document say so." It does not answer "is this
the kind of body that says so at all," and the graph treats those as one question.
A statutory formula with four enumerated inputs and a central bank that deliberates
are indistinguishable in the data, and the second reads as under-researched when it
is correctly characterised.

The prompting case was the FOMC Statement, and the useful discovery is that it is
**not a hard case**. It discloses its inputs — the Statement on Longer-Run Goals
names PCE inflation, the dual mandate is statutory — without disclosing an
algorithm. `relationship_type` already carries that distinction, exactly as it does
for the Bank Rate against the prime rate. Nothing was needed at the edge level.

What was missing is at the node level: **`determination`: `formulaic` |
`discretionary`**, plus **a disclosure ratio** showing how many of a node's inputs
are documented against how many were searched for and not found. The denominator
already exists in `_dropped` and is currently unread.

### Rejected, with reasons, so they are not re-proposed

**Confidence as glow, on a relative rule** — glow the undocumented edges when
documented ones predominate and the reverse when they do not. The instinct that
proportion is informative is right; the mechanism inverts its own meaning. An
edge's appearance would depend on the documented ratio *elsewhere in the corpus*,
so a batch landing in Alberta could flip what glow means in Washington. That is the
defect *filtering is a view, never a recalculation* exists to prevent. The
salvageable version is the ratio computed per node, which is the disclosure ratio.

Glow is also the worst channel available: bloom threshold sat at 0.5 for five
sessions while the brightest node reached 0.36, so zero nodes ever crossed it. If a
third evidence tier is wanted, extend the dash vocabulary instead — it survives at
three pixels and does not fight the glow pass.

**A confidence weight threshold.** Converts a continuous judgement into a cliff and
hides its own failures; the bloom constant is the cautionary tale. Noted also that
`strength`, a per-edge weight override, already exists and is used on **0 of 195
edges**. It should stay unused — a hand-tuned edge weight is exactly the "ranking
depends on what somebody found plausible" failure the evidence standard prevents.

## Two previously-settled passages now carry caveats

Worth flagging separately, because amending settled text is a heavier act than
adding to open questions.

**The authority-score decision** now points at the retention finding. Any ranking
is provisional until that is resolved.

**"When the ranking looks wrong, first ask whether the graph is wrong"** now has a
rival explanation. The doctrine has been the right diagnosis four times, but two of
those cases — SEPH and the Alberta ministerial guidelines — are one-weak-edge nodes
keeping 66.7% of their rank. *"The graph is thin here"* and *"this node discloses
one input weakly"* predict the same symptom, and adding data will not resolve the
second. The check is now: look at out-degree first. If it is 1, the ranking is
partly an artifact.

## Known problems

Everything in V0.7's list is unchanged and still true — four Canadian shades
unjudged on a real display, no reset-camera button, drop lines falling to a deleted
floor, focus dimming too weak, `last_updated` null across all 121 nodes, milestone
3's pulse on the wrong quantity, one orphan. Nothing was touched.

New, or newly precise:

**21 seed edges still fail the evidence standard.** Down from 27; the six with a
research copy were fixed by the duplicate rule. These have no fallback, so each
needs a document found, or deletion, or demotion to `implied` — and *finding a
document is not the default outcome.* `fed-fomc-statement -> bls-cpi` has a `basis`
that hedges, and an edge whose own reasoning hedges is not one to go hunting for a
URL to justify.

**`boc-mpr` and `fed-h15` still fall out entirely** under the strict standard, and
the Bank of Canada rate corridor is still a five-node island.

**The `determination` field is decided and not built.** One field, plus a
judgement-call backfill across 121 nodes.

**The disclosure ratio is decided and not built,** but no longer blocked — the
denominator is data now, so what remains is card layout and deciding what to show
for the majority of nodes that have no dropped notes at all.

**Whether within-system structure needs its own relationship kind** is open and now
written down. `bea-gdp -> bea-pce` is a definitional identity, not a fetched input,
and the graph has one vocabulary for both. Worth settling before the
national-accounts and input–output material arrives, since that cluster is mostly
this shape.

**`npm run validate` cannot run against the project folder in a Linux sandbox**,
because `node_modules` holds Windows `esbuild` binaries. Reinstalling in place would
break the local Windows setup. The workaround used here: copy `src`, `scripts` and
the configs to a scratch directory and install there. The lib/data/scripts subset
has no external dependencies beyond node builtins, so `typescript` + `tsx` +
`@types/node` is enough — react and three are not needed to typecheck or validate.

1. **Resolve the 21 unevidenced seed edges.** The last of Tier 0 and the only thing
   still gating expansion. Needs a research budget rather than a decision. Start
   with `boc-policy-rate -> statcan-cpi` — one URL reconnects five nodes.
2. **The `determination` backfill**, while the distinction is fresh. Doing it before
   the interprovincial work is cheaper than retrofitting it afterwards, because that
   material is largely statutory formulas and classifies quickly.
3. **The disclosure ratio in the hover card.** Small now that the data exists, and
   it is the visible payoff for the `_dropped` work.
4. **Set the slider defaults to the values that were just found legible** — haze
   around 35%, glow around 55%. They were verified by hand this session and the
   defaults have not been changed to match, which is how a looked-at finding
   quietly expires.
5. Only then the expansion tiers, starting with the Equalization RTS edges — the
   node already exists as a single-edge leaf.
