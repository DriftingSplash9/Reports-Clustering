# V1.5 — Rollup 1. Covers V0.1 through V0.5.

Written 2026-07-29, after V0.6 existed. The window is still V0.1–V0.5: rollup 2
begins at V0.5, so anything V0.6 revised is rollup 2's problem by design. What
that overlap does *not* license is asserting something already known to be
false, so where V0.6 has settled a matter this file says so in one line and
moves on.

This replaces the five session logs as reading. They are not deleted and the
human still audits them; but a new agent should read REPORTS.md, this file, and
the latest session log, and nothing else.

**What was pruned:** every intermediate count (18 reports, then 30, 33, 118),
the doc-reconciliation bookkeeping in V0.3, a stale `node_modules` from setup
day, bloom values tuned and re-tuned, a lost OrbitControls target, and every
"recommended next step" that has since been taken.

**What was promoted rather than kept:** everything learned about *working with*
the corpus — which documents are usable, how to run a research batch, when to
distrust a ranking — moved into REPORTS.md, because adding and editing nodes
never stops being the job and that guidance should not sit in a file a later
rollup will consolidate away. This file keeps the incidents that explain why
those rules exist.

The five logs are 11,900 words. What is below is the fifth of them a new agent
would be worse off without.

## Decisions that still bind

### The evidence standard
Documented citations only. Every dependency carries an `evidence_url` pointing
at a document that explicitly names its source. **If no document says it, the
edge does not exist** — however obvious the relationship looks. Enforced by
convention, not by code.

It has a visible cost and the cost is the point: LGFF Operating is a real $60
million-a-year programme, and it is dropped from the graph on every build
because no document names its inputs. That is the standard working.

This is the most important rule in the project. Everything else is negotiable.

### Position encodes only the edges
An early renderer pulled nodes to fixed heights by jurisdiction level. It was
wrong on its own terms: international bodies *consume* national statistics, so
they are downstream in influence, yet any stack puts them on top — pointing
opposite to the flow the graph exists to show. Provinces have the mirror
problem, thirteen peers forced into a rank they do not have. Deleted.

If a vertical axis is ever wanted, the honest version is depth in the dependency
graph — computed from edges, not asserted, and it inverts correctly for the
international case.

### Arrows point the way influence travels, not the way dependency is stored
The data model stores *source depends on target*. The renderer draws and pulses
from the foundational report outward to its dependents, because that is the
direction the user is being asked to read. **The two disagree deliberately.**
Written down here so nobody "fixes" it.

Edges therefore carry a `key` in the data model's direction, computed once at
build time. Deriving it at lookup time means flipping an already-flipped pair —
the kind of double negative that lights the right nodes and the wrong lines.

### No labels on nodes
Always-on labels competed with size for attention and turned the dense centre
into grey mush, defeating the one thing the graph exists to show. Identity moved
to hover. **Importance is read at a glance; identity is on demand.**

### Field of view 24°
The most important number in the renderer. At a wide angle apparent size is
dominated by distance from the camera, so a peripheral leaf near the lens
outdraws the foundational report behind it — inverting the one rule the graph
expresses. A long lens compresses depth so a node reads as large because it *is*
large.

This has a cost that only appeared at scale; see Live problems.

### Authority is weighted PageRank with retention
Damping 0.85, edge weights `calculated_from` 1.0 / `uses_data_from` 0.8 /
`methodology_depends_on` 0.5 / `cites` 0.25, and **`SELF_RETENTION = 1.0`
applied only to nodes that have outgoing edges.**

The retention exists because textbook PageRank transfers *all* of a node's rank
along its outgoing edges, and here that produced a specific absurdity: a set of
Alberta ministerial guidelines outranked the US CPI on two incoming edges,
because both assessment rolls pointing at it had exactly one outgoing edge each
and drained everything they had into it.

**The deeper reason, which matters more than the instance: out-degree in this
graph is a fact about our research, not about the world.** An assessment roll
really rests on the regulations, the quality guidelines and market sales data;
the graph knew about one because one had been documented. Full transfer lets
whichever dependency was researched first inherit an entire node's authority — so
the least complete part of the graph produces the loudest result.

Retention is applied only to nodes with outgoing edges. Giving a true sink a
self-loop lets it hoard: at damping 0.85 a pure sink that keeps everything
settles at over five times its inflow, which is the original bug made worse.

Raw in-degree is computed alongside and kept visible. The two rankings
disagreeing sharply is the signal that edge data is wrong.

### Size is rescaled authority, then square-rooted
PageRank has a floor, so raw authority spans only about 0.2–1.0 — a radius ratio
under 2×, far too subtle to read. `size_score` rescales across the observed
range. Radius is `min + sqrt(size_score) * (max - min)` with min 2.2 and max 8,
because the eye compares area and linear scaling makes the top node swamp
everything.

### The focus cone is full, not one hop
Selecting a node lights everything transitively reachable, both directions,
under two independent toggles. The objection is that a full cone lights too much
of the graph — and **the worry inverts with scale**, which is now measured
rather than argued:

| Graph size | Median cone |
|---|---|
| 33 nodes | 5 |
| 118 nodes | 11 |
| 121 nodes | 11 |

The median cone is a smaller fraction of the graph at 121 than at 33. Three
sessions of holding.

Dimmed, never hidden: the surrounding structure is the context that makes a cone
mean anything. Pulses are suppressed rather than dimmed, because motion outdraws
brightness — a dim moving dot pulls the eye harder than a bright stationary one.

### Research lands incrementally, one slice per file
Findings go to `src/data/research/*.json` (18 slices), merged by a loader that
tolerates edges pointing at reports not yet researched. Slices arrive in any
order. **Anything long-running writes as it confirms, never at the end.** See
Mistakes.

### Published commercial sources are in; confidential ones are not
Decided V0.4, implemented V0.5. Sources that are published but not official —
J.D. Power supplying every used-car price in the US CPI, ICE Brent and Argus
Mexico Maya named verbatim in Alberta's bitumen valuation regulation — become
nodes marked `source_kind: 'commercial'`, drawn grey, and **excluded from the
authority calculation by subtraction**. Sources that are never published (the FR
2644 form, the CIRO repo feed) stay out entirely.

This was never an evidence problem — the BLS Handbook documents J.D. Power more
plainly than many edges already in the graph. The node rule was what failed, so
the node rule bent.

Excluding by subtraction rather than by zeroing makes official scores bit-for-bit
identical to a graph where the commercial nodes never existed, so the view toggle
provably reshuffles nothing. `npm run validate` checks it every run.

### Filtering is a view, never a recalculation
A filter subtracts nodes from the picture and changes nothing else — no
recomputed authority, no re-run layout. Enforced by applying visibility through
the force-graph library's visibility accessors, which filter only what is drawn
while the simulation still runs over the full node list.

The constraint is why filtering is safe to offer at all: a filter that reshuffled
the graph would make every comparison the user had just made silently wrong, with
no way for them to notice.

One predicate type, three consumers — the commercial toggle, jurisdiction
filtering, and search. **Search shares the predicate and nothing else.** Search
locates; filters hide.

### Cadence is three quantities, and the third lives on the edge
Decided V0.4. Publication rate and change rate on the report, transmission rate
on the *dependency* — the same CPI release reaches the Monetary Policy Report
monthly and the Alberta escalator annually, and no field on the CPI can say that.
Implemented in V0.6.

## Mistakes worth not repeating

### Five research agents, ~900,000 tokens, nothing written
Five subagents were told to research everything and write one file at the end. A
session limit killed all five before any had written anything. Two were within a
step of finishing.

**The cause was the instruction, not the limit** — a single point of failure at
the last step. The fix was proven at scale in V0.4: eight agents across two
batches, 45 new nodes, zero dangling edges, nothing lost.

The rules that came out of it are now standing procedure in REPORTS.md under
*Running research in batches*. This entry exists so that a future agent tempted
to relax them knows what they cost.

### The room that was never mounted
Two rounds were spent adjusting colours and opacity on objects that were not in
the scene. `three-forcegraph` builds its objects asynchronously after
`graphData()` is set, so at React effect time every node still had
`x === undefined`; the camera fit hit its guard and returned early, `onBounds`
was never called, and App gates the entire room on `bounds`.

**When a toggle has no visible effect, check whether the thing is mounted before
adjusting how it looks.**

### When the ranking looks wrong, ask whether the graph is wrong
Closing the sink leak sent two Grande Prairie assessment rolls to #1 and #2 and
dropped the US CPI to #8. That was not a second bug — it was an honest report of
a **curation imbalance**: 24 of 47 nodes were Alberta municipal documents,
densely interlinked, while the federal cluster was sparse. The metric had stopped
hiding it, and **the cure was data, not tuning.**

Now standing doctrine in REPORTS.md, where it applies to every future ranking
surprise rather than to this one.

### Two effects writing the same accessor
Link colour and particle count were briefly set in two places, so toggling Edges
could silently undo the focus dimming — whichever effect ran last won. The focus
effect owns them alone now.

Related, and the same class: mounting and unmounting `EffectComposer` re-routes
the whole render through an offscreen buffer with different colour handling,
which shifted the background tint of the entire scene and made the Glow switch
appear to do the horizon's job. The composer stays mounted; the toggle only
changes intensity.

### Three sessions shipped visuals nobody had looked at
V0.1, V0.3 and V0.4 all closed with "not verified: how any of it looks". V0.5
finally looked, and found three visual decisions that had quietly expired — see
Live problems. **The build output cannot make a visual judgement, and the logs
show it takes about a session per unlooked-at change before the debt comes due.**

### Describing a V as a chain
The project's flagship example was written up as a single directed chain from a
municipal funding formula to the national unemployment rate. The second half
reverses: the Labour Force Survey *depends on* the Census, so it is a sibling
consumer, not a further step. It is a **V meeting at the Census**. Still a
documented path across four levels of government — but calling it a chain claimed
something the edges do not say, and it was the example the project led with.

## Findings about the subject matter

What was learned about *working with* the corpus — which documents are usable,
how to run a research batch, when to distrust a ranking — has moved to REPORTS.md
under **Working with the corpus**, because adding and editing nodes never stops
being the job and that guidance should not be sitting in a document a later
rollup will consolidate.

What stays here is what was learned about the subject itself.

- **The Census is one hop further back than anyone expected.** Federal transfers
  do not run on it directly: the regulations prescribe the July 1 population
  *estimate*, moved from June 1 by SOR/2023-230, which is the postcensal
  programme — the census adjusted for undercoverage plus births, deaths and
  migration. That extra hop is why the Census is the highest-authority node in
  the graph, and it is not a result anyone would have predicted.
- **Alberta's largest revenue line is set by a commodity exchange.** Oil Sands
  Royalty Regulation s.29 defines the royalty rate in terms of the NYMEX WTI
  settlement price, converted at the Bank of Canada's published rate, with a
  statutory fallback for the day the Bank stops publishing.
- **A statute contains a correction procedure for a statistical revision.** CPP
  s.18(7) requires the Minister, on the advice of the Chief Statistician, to
  splice StatCan's average weekly earnings back onto its former basis if the
  definition changes by more than 1%. Legislation anticipating a methodological
  break upstream.
- **Alberta's disability benefit rests on 27 reports and reaches a UN standard
  in four hops.** Bill 32 (2024) replaced direct Alberta-CPI rules with a single
  "Alberta escalator" in the *Alberta Personal Income Tax Act* — so the income
  tax bracket indexation factor now sets AISH payments, and its 2% cap bound in
  both 2025 and 2026.
- **Headline public numbers demonstrably rest on private data.** Every used-car
  price in the US CPI comes from one company. This is what forced the
  commercial-source decision.

## Live problems

**`last_updated` is null everywhere.** Present in every session log from V0.1 to
V0.5 without exception, across 18 nodes and then 121. Never wired to a source,
left null rather than invented because fabricated dates would corrupt the cadence
work. It is now the blocker for milestone 3: a rate without a last observation
cannot say when the next one is due.

**The default view is wrong at 121 nodes.** Found in V0.5, the first session that
actually looked:

- The auto-fit camera fits the *room*, not the node cloud, so on load the graph
  occupies about a fifth of the frame above mostly empty floor. At 33 nodes the
  two were comparable sizes and this was invisible.
- Zoomed in far enough to read a node, the centre is opaque. This is occlusion,
  not a weak size encoding — top-to-median radius is 2.14×, which is 4.6× in
  area, and only 13 of 121 nodes sit near the minimum.
- **Distance haze off has become a liability.** It was switched off because it
  fights the 24° lens, which was right when nothing occluded anything. The lens
  suppresses parallax by design, so with fog off there is now no depth cue at
  all. Revisit as "how much fog", not "fog or not".

**Out-of-focus node dimming is weaker than the code believes.** Comparing
selected and cleared frames, what actually changes is the edges — they dim and
their pulses stop. At `DIM_NODE_OPACITY` 0.34 under bloom, an out-of-focus sphere
still reads as fully coloured. The cone is legible, but not for the reason
intended.

**One orphan remains** — LGFF Operating, dropped every build. The standard
working, not a defect.

**The Alberta health delivery layer is mid-restructure.** The Provincial Health
Agencies Act split AHS into four sector agencies in 2024-25; two nodes describe
entities in transition and will need revisiting.

**Two session logs were written that nobody asked for.** V0.5 and V0.6 were both
produced off a standing instruction in REPORTS.md — "at the end of a meaningful
session, write the next-numbered log" — which an agent read as standing
authority to act once it judged a session meaningful.

Worth being precise about what went wrong, because the first fix was also wrong.
The *judgement* was fine: both were sensible stopping points and both logs are
useful. The error was acting on it silently. The rule now is offer-then-write —
an agent may notice and say "now's probably a good time to wrap up V0.7, want me
to?", and then wait. The first attempt at a fix removed the agent's ability to
propose at all, which threw away the useful half.

The rollup also now rides along with the fifth log rather than being its own
deferrable task. Recorded here because the failure was in a document telling an
agent to do work, which is a thing this project has a lot of.
