## The filter layer

`src/lib/filter.ts`. A `NodePredicate` over `ScoredReport`, a `FilterState` that
compiles to one predicate, and `applyFilter` returning a `VisibleSet` of node
ids and edge keys. An edge survives only if both endpoints do.

**The layer's whole contract is that it is a view and nothing more.** It does
not recompute authority, does not re-run the layout, does not touch the data.
Turning a filter on subtracts spheres from the picture; everything remaining is
the size it was and where it was. That is not a convenience — a filter that
reshuffled the graph would make every comparison the user had just made silently
wrong, with no way for them to tell.

Three features consume it, and REPORTS.md was explicit that they must share
rather than accumulate a tenth boolean in the view panel:

- **the commercial-source toggle**, the first instance;
- **jurisdiction filtering**, which is what proves the layer is reusable rather
  than asserting it;
- **search**, which shares the predicate type and *only* that.

**Search deliberately does not filter.** Typing three letters must not make a
hundred nodes vanish — the surrounding structure is the context that makes the
found node mean anything. Search locates, filters hide. The one place they have
to agree is that search never offers a node the filter has removed, or choosing
it would fly the camera to an empty patch of space.

### How visibility is applied without re-simulating

Through three-forcegraph's `nodeVisibility` and `linkVisibility` accessors,
which filter only the WebGL digest. The d3 simulation at the bottom of the
library still runs over the full node list, so hiding a node freezes everything
else exactly where it is. Rebuilding `graphData` instead — the obvious approach —
would re-run the layout and scatter what the user was looking at, which is the
one thing this must never do.

Two details that cost time and are worth not rediscovering:

- **The library deallocates objects it removes from its own digest.** An earlier
  version disposed superseded meshes in `nodeThreeObject`; that was redundant,
  and worse, it read as though something were being managed there that was not.
- **A count-watching guard is not enough to re-apply focus after a filter
  change.** A change that hides three nodes and reveals three others leaves the
  mesh count where it started, and three freshly built spheres would sit there
  ignoring the current selection. The applied count is now invalidated outright
  rather than compared.

**Filtering a link hides its line, its arrowhead and its pulses together**,
because all three digest off the visible-link list. That is the right coupling
here and the wrong one for the Edges toggle, which hides lines while keeping the
pulses on purpose — so that one still works through the material. Two different
questions, two mechanisms; worth keeping straight.

### Cones respect the filter

`buildFocusIndex` now takes the visible set and walks the visible subgraph. With
commercial sources hidden, "what does this rest on" has to mean "among official
releases" — a cone quietly routing through a node that is not on screen would
report a chain the picture contradicts.

The effect is not cosmetic. **The Alberta bitumen valuation cone goes from 5
nodes to 2 when commercial sources are hidden.** Three of the five things
Alberta's bitumen floor price rests on are private price feeds. That difference
*is* the feature.

## Commercial sources are in

Implemented from the V0.4 decision. `source_kind?: 'official' | 'commercial'`,
absent meaning official — a required field would have been 118 edits all
asserting the same thing.

**Four nodes, and one of them was already in the graph.** `nymex-wti-settlement-prices`
has been sitting there since V0.4 as an `institutional` node accruing rank on
three incoming edges: a commercial exchange as a terminal sink, which is
precisely the shape that caused the sink-leak bug. The scope rule was already
being violated in one place and nobody had noticed, because the violation looked
like an ordinary node. Reclassifying it was as much of the work as adding the
other three.

Promoted from `_dropped`:

- **J.D. Power Valuation Services** ← BLS CPI. The Handbook of Methods states
  outright that all used-car and truck prices, and new vehicle transaction
  prices, come from J.D. Power.
- **ICE Brent** ← Alberta BVM components. Regulation s.1(3)(f), by name.
- **Argus Mexico Maya** ← Alberta BVM components. Regulation s.1(3)(e) names the
  company: "as published by Argus Media Inc."

**Still out, and for a reason worth distinguishing.** The WCS-WTI broker index
and the CAPP Equalization Steering Committee values failed the *old* officialness
rule and would now pass it — except they fail a different test. BVM Regulation
s.1(3)(c) sets the WCS index from "the commodity brokers specified" in a list the
Minister sets by order, so there is no stable publication to point a node at.
Commercial is now allowed; unidentifiable is not, and no rule change fixes that.
Recorded in `_dropped` with that reasoning, because the distinction will come up
again.

### The guarantee, and why it is checked rather than stated

Authority is computed over the official subgraph by **subtraction** — commercial
nodes and every edge incident to one are removed before ranking, then the
commercial nodes are appended at authority 0. Not by zeroing them mid-iteration.

The difference buys a property: official scores are bit-for-bit what they would
be if the commercial nodes had never been added. So the toggle provably
reshuffles nothing — no size changes, no rank changes, no re-layout — and the
two views differ only in which nodes are drawn. **That is the entire case for
offering the toggle at all.**

It is also easy to break later. One outgoing edge from a commercial node, or one
caller reaching past `isOfficial`, and it dies quietly. So `npm run validate`
now rebuilds the graph without the commercial nodes and asserts every official
score comes back identical:

```
COMMERCIAL SOURCES — 4 nodes, outside the authority calculation
  · J.D. Power Valuation Services Vehicle Price Data — 1 depend on it
  · NYMEX Light Sweet Crude Oil (WTI) Futures Daily Settlement Prices — 3 depend on it
  · ICE Brent Crude Futures Daily Settlement Prices — 1 depend on it
  · Argus Mexico Maya Spot Price, FOB US Gulf Coast — 1 depend on it
  ✓ official scores identical with and without them — the toggle reshuffles nothing
```

It also flags any commercial node that is not a sink, because that is the shape
that would matter if anyone ever put them back in the calculation.

Commercial nodes render grey — deliberately off the palette rather than a sixth
hue. The five level colours encode publisher scope and a commercial provider does
not sit anywhere on that axis. They show authority as `—`, not `0.00`: zero
reads as a measured result rather than a question the graph declines to ask.
`in_degree` sits next to it, which is where their real weight shows.

## Search

`src/lib/search.ts`. Every query token must match somewhere, so adding a word
narrows. Fields are weighted title, id, publisher, region, description.

**The id is weighted level with the title, not below it.** It is a curated
identifier, not incidental text, and it carries the acronym the title often
spells out: StatCan's release is titled "Consumer Price Index" and its id is
`statcan-cpi`. Weighting ids lower ranked the American CPI-U above the Canadian
CPI that thirteen other reports are built on — a real ordering bug caught only by
running the query. Level weighting lets the two tie and the authority tiebreak
settle it.

**Choosing a result selects the report and flies the camera to it.** Selection
alone was the version that did not work — it lit a cone somewhere off screen and
left the user no better off. The flight approaches along the direction the user
was already looking from; choosing a new angle would be the renderer deciding
there is a right way round to view the graph, which is the same mistake as
sorting nodes by height.

The legend and the jurisdiction filter are the same control. Keeping them apart
would have meant printing every colour and count twice and hidden the more useful
fact: the thing you can switch off is exactly the thing the colour names.

## The layout at 121 nodes, finally looked at

V0.4 listed this as not verified. It has now been looked at, and it is the most
useful thing in this session.

**1. The default framing shows the graph too small to read.** The auto-fit
camera fits `max(nodeRadius, frame.extent * 1.42)` — the *room*, not the nodes.
At 33 nodes the room and the node cloud were comparable and this was invisible.
At 121 the cloud is a compact ball inside a much larger room, and on load it
occupies roughly a fifth of the frame height with the platform sitting far below
it. The first thing a new viewer sees is mostly empty floor.

**2. Zoomed in to where nodes are readable, the centre is opaque.** Heavy
overlap, foreground and background indistinguishable. This is an occlusion
problem, not a size-range problem — the size encoding is healthy:

```
radius  max 8.00  p90 5.33  median 3.74  min 2.20
max/median 2.14×   max/min 3.64×
only 13 of 121 nodes sit within 30% of the minimum radius
```

A 2.14× radius ratio between the top node and the median is 4.6× in area, which
reads fine in isolation. It does not read when a small node in front of a large
one and a large node behind a small one look identical.

**3. The distance-haze decision has expired.** V0.4 turned fog off on the
grounds that it fights the 24° lens — the long lens exists so a node reads as
large because it *is* large, and fog adds a second depth cue on top of the one
being deliberately suppressed. That reasoning was correct at 33 nodes, where
nothing occluded anything. At 121 the result is a scene with **no depth cue at
all**, and the cloud reads as a flat disc of confetti. The lens suppresses
parallax; fog was the only thing left. This is the specific decision to revisit,
and it should be revisited as "how much fog", not "fog or not".

**4. Node dimming under focus is too weak; the edges are carrying the cone.**
Selecting the Census of Population lights 35 of 121 nodes, and comparing the
selected and cleared frames side by side, what actually changes is the edges —
they go dim and the pulses stop. The nodes barely move. `DIM_NODE_OPACITY` at
0.34 plus bloom leaves an out-of-focus sphere reading as a fully coloured ball.
The cone is legible, but not for the reason the code thinks it is.

**5. Filtering turned out to be the accidental fix for density.** Hiding the 62
federal nodes made the graph immediately readable — structure visible, individual
nodes distinguishable, no mush. The filter layer was built for scope questions
and it answers the legibility question too. That was not the plan and it is
probably the most useful thing to come out of the session.

## Known problems

**The cadence model is still unimplemented and still blocks milestone 3.**
Unchanged from V0.4: `update_frequency` is still on the node, the reference
period is still not on the edge, and the six documented reference periods are
still sitting as prose in `basis` fields. This was recommendation 2 in V0.4 and
it was not done this session. It is now the oldest outstanding decision.

**`last_updated` is null everywhere.** Unchanged, now across 121 nodes.

**Default view is wrong at this scale** — see layout findings 1 and 3.

**One orphan report remains** — LGFF Operating, dropped every build because no
document names its inputs. The standard working.

**The Alberta health delivery layer is still mid-restructure.** Unchanged from
V0.4; two nodes describe entities in transition.
