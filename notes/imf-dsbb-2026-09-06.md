# dsbb.imf.org — how to read it (2026-09-06)

Companion to `notes/imf-elibrary-2026-09-06.md`. Same host family, completely
different mechanism. **`www.imf.org` 403s everything; `elibrary.imf.org` serves
books; `dsbb.imf.org` serves the Data Standards Initiatives and needs this recipe.**

## The trap

Every path under `dsbb.imf.org` returns HTTP 200 with a near-identical ~44 kB
page. It is an **AngularJS SPA** — the tell is `ng-view`, `ng-controller` and
`{{country.CountryName}}` sitting unrendered in the HTML. Extracting text from
any of those pages gives you the navigation menu and nothing else.

At least seven `_dropped` entries across the corpus record dsbb.imf.org as
`unreadable-source` or "JS-walled" on exactly this basis (Libya, Vanuatu,
Tajikistan, Lebanon, Guatemala, Honduras, Haiti, and a Gabon `denied`). **Those
are claims about the fetcher, not the site** — PLAYBOOK-CORPUS §6, "claims about
the world that are really claims about your tools". The site was open the whole
time. They are re-openable; none was re-opened in round 4.

## Prose: one REST call

    https://dsbb.imf.org/api/staticcontent/getPageContentByContainerID?containerID=<ID>

Returns JSON: `{"Containers":[{"ContainerID":..,"PageTitle":..,"Content":"<html>"}]}`.
Plain curl with a browser UA. No token, no cookie, no referer.

**Finding the container ID.** The Angular route config (`/scripts/app-conf.min.js`)
maps `/{section}/{page}` to `static/{tranSec}/{page}.html` where `tranSec` is the
section lowercased with dashes removed and the literal string `plus` removed —
so `sdds-plus` and `sdds` share a template directory. Beside each template sits
`{page}Controller.min.js`, and the controller's `initializeController` calls
`mGetStaticContent("<ID>", "<countryType>")`. Read the ID out of the controller:

    curl https://dsbb.imf.org/static/sdds/overviewController.min.js?ver=v126

IDs confirmed 2026-09-06:

| page | containerID |
|---|---|
| /sdds/overview | `Overview_SDDS` |
| /sdds-plus/overview | `Overview_SDDSPlus` |
| /sdds/statistical-methodology | `Int_Accpt_STA_Method_SDDS` |
| /sdds-plus/statistical-methodology | `Int_Acc_STA_Method` |
| /e-gdds/overview | `What_Is_GDDS` |
| /e-gdds/guide | `Guide_GDDS` |
| /dqrs/DQAF | `DQRS_DQAF_English` |

Note the two methodology IDs are NOT parallel (`Int_Accpt_` vs `Int_Acc_`) — do
not guess one from the other. A wrong ID returns `{"Message":"02_Malformed
request, no data was found..."}`; an ID that exists but errors returns `05_`.

## PDFs: a plain static directory

`https://dsbb.imf.org/content/pdfs/<name>.pdf` is served to bare curl, no SPA in
the way. Single-column, so `pdftotext` is fine either way. The eight
dataset-specific DQAF frameworks:

`dqrs_Genframework` (generic) · `dqrs_nag` · `dqrs_cpi` · `dqrs_ppi` ·
`dqrs_gfs` · `dqrs_psds` (Aug 2024, the only one revised since 2013) ·
`dqrs_MonetaryAcc` · `dqrs_bop` · `DQAF_EXD_Statistics`

Each has a Methodological Soundness section opening "The methodological
soundness dimension is assessed against the guidelines outlined in …", which
names the governing manual in body prose. That sentence is what bought eleven
edges in round 4.

## What is still 403

`www.imf.org` refuses every path from both networks, including the SDDS and SDDS
Plus Guide PDFs that the DSBB pages link to
(`/external/pubs/ft/sdds/guide/2013/sddsguide13.pdf`,
`/external/pubs/ft/sdds/guide/plus/2015/sddsplus15.pdf`). Those two Guides are
the obvious next targets and are NOT reachable this way; try elibrary, or a
Chrome read.

## Addendum: elibrary periodicals (WEO, Fiscal Monitor, GFSR)

`notes/imf-elibrary-2026-09-06.md` covers the manuals, which are books. The
three flagships are **shelved as books too** — the "different URL shape" HANDOFF
expected does not exist. What differs is how you find the ISBN.

- **One ISBN per ISSUE per LANGUAGE.** The manuals' one-ISBN-per-language trap,
  multiplied by two issues a year.
- **The serial landing page is useless to curl.** `/display/serial/world_economic_outlook?bot=bot`
  returns 200 and ~457 kB, and its issue list is client-rendered — no ISBN
  appears anywhere in the bytes. Same for `fiscal_monitor` and
  `global_financial_stability_report`.
- **A dated search is what yields the ISBN**:
  `https://www.elibrary.imf.org/search?q=Fiscal+Monitor+April+2025&bot=bot`,
  then read `/downloadpdf/display/book/<isbn>/` links out of the HTML. An
  undated search returns issues from the 1990s and 2010s first.
- **Whole issue**: `/downloadpdf/display/book/<isbn>/<isbn>.pdf`.
  **Chapter**: `/downloadpdf/display/book/<isbn>/CH00N.pdf`, uppercase CH,
  three digits. Chapter numbering is per issue and is not listed anywhere
  fetchable — walk CH001..CH007 and read each first page; a miss is a clean 404.

April 2025 ISBNs and the chapters that carry the methodology:

| publication | ISBN (English) | methodology chapter |
|---|---|---|
| World Economic Outlook | 9798400289583 | `CH004` — Statistical Appendix |
| Fiscal Monitor | 9798229002516 | `CH005` — Methodological and Statistical Appendix (`CH004` is the Glossary, also useful) |
| Global Financial Stability Report | 9798229003261 | not yet looked at |

These are single-column and `pdftotext` reads them cleanly — the two-column
trap is the manuals, not the flagships. **Do not quote from the WEO's Table G**:
pdftotext renders it as column soup with no contiguous span.

## Addendum 2: the country endpoints (added 2026-09-06 evening)

Two more endpoints, found while re-opening the eight `unreadable-source`
refusals. Between them they answer "which dissemination tier is country X in,
and when did it actually implement" for every IMF member, definitively, to a
plain browser-UA curl.

    https://dsbb.imf.org/api/country/getcountrybytype?countryType=EGDDS
    https://dsbb.imf.org/api/country/getcountrybytype?countryType=SDDS
    https://dsbb.imf.org/api/country/getcountrybytype?countryType=SDDSPlus

Returns `{"CountryListByAlphabets":[{"Alphabet":"A","CountryGroup1":[…]}]}` —
walk every `CountryGroup*` key in every alphabet block. Counts on 2026-09-06:
**110 e-GDDS · 49 SDDS · 32 SDDS Plus**. Sanity check that the lists are current:
49 + 32 ≈ the SDDS overview page's "80 subscriptions", because the SDDS list
excludes countries that moved up to SDDS Plus. `NSDPUrl` is populated for SDDS
rows and empty for **every** e-GDDS row — that is a property of the list shape,
not of any country, so do not read an empty `NSDPUrl` as non-participation.

    https://dsbb.imf.org/api/country/getsubscriptiondateInfos?countryType=EGDDS&ContainerID=HistoryImportantDateGDDS

Returns a flat list of 110 rows, one per participant, and it is the data behind
`dsbb.imf.org/e-gdds/important-dates-history` — the page headed "Enhanced
General Data Dissemination System / Important Dates", columns *Participant* /
*Date Metadata First Posted on the DSBB* / *Date e-GDDS NSDP First Posted*.

**`ComplianceDate` is the discriminator and the whole point.** It is the NSDP
first-posted date. Non-null = the country genuinely implemented e-GDDS. Null =
it has legacy GDDS-era metadata on the DSBB and never posted an NSDP. Being on
the participant list is NOT by itself evidence of implementation — Libya,
Lebanon and Haiti are all on it with null ComplianceDate.

Grading note: the payloads do not spell out "Enhanced General Data Dissemination
System" — the artefact is named by the page that consumes them and by the
request. That caps a citation to these endpoints at **B**. A Chrome read of the
rendered Important Dates page, where the heading and the country row are on one
page, clears the A bar under the 2026-09-04 direct-read ruling.
