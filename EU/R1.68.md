## Decisions and techniques that now bind

### CIRCABC: navigate direct, never click through the shared listing

G.65 found the shared 100-row folder listing (one URL lists every country's
EDP-inventory file — name, date, version, size, superseding Eurostat's
unreliable per-country accordion UI) and a first staleness trap: clicking a
new country's Preview link before the previous PDF.js viewer's own close had
registered could re-show the previous country's content. The documented fix
was `Escape`, wait, then click.

**G.68 found a second, worse variant of the same bug, and it changed the
method.** The same click-path staleness can leave the viewer showing the
*previous* country's content **with no error at all** — same page count,
same text, nothing announcing the failure. This is more dangerous than the
loud `InvalidPDFException` G.66 documented for non-current file-history
versions, because a silent wrong-country read looks exactly like a right one
until someone checks. **The fix that stuck: navigate directly to each
document's own `.../library/{uuid}/details` URL — a fresh page load — rather
than clicking Preview from the shared listing.** Slower, one extra
navigation per country, but eliminates the staleness risk structurally
rather than by timing discipline. This is now the default method for any
future CIRCABC work in this project, superseding G.65's close-then-click
fix rather than sitting alongside it.

Two countries (Malta, Hungary) that appeared to fail render entirely under
the old method rendered cleanly under the new one — the same bug class, not
a distinct structural problem, per G.68 finding 4.

### Non-current CIRCABC file-history versions do not preview — plan around it, not through it

G.66: six attempts to open a superseded version (Cyprus, Czechia ×3, Greece)
all failed identically with `InvalidPDFException: Invalid PDF structure`;
every *current* version opened cleanly in the same sessions. Six for six, no
exceptions, three unrelated countries. **Budget for filename-based dating of
the older endpoint, not a verbatim read**, and say so per node — which is
exactly what `cy-`, `cz-` and `el-edp-inventory` now do in their own
`cadence_note` fields.

### The CIRCABC filename-date convention is weaker than four countries made it look

Established as reliable across DE/BE/HR/BG (filename date = title-page date,
every time). **G.68 broke it on the very next batch.** United Kingdom and
Netherlands are outright mismatches — filename and title page disagree by
eight months and over a year respectively, reported and not adjudicated per
§3. Poland and Slovakia are a different failure shape worth keeping
separate from a mismatch: both dates on the page agree with each other, but
the *filename* tracks whichever dated line appears **last** on the page (an
"Updated" line, a "Sent to Eurostat on" line) rather than the document's own
primary compilation date. **The convention tracks page position, not
document identity.** Check the title page before trusting a filename date on
any future CIRCABC document; four confirming countries were not enough to
call it settled, and it wasn't.

### Mint-anyway is a scoped ruling, not a rule change

G.68's central decision. All 21 remaining CIRCABC countries carried exactly
one dated edition — under `Research.1.md` §4's ordinary rule ("a single
edition with no second one anywhere in sight is still not a node"), none
would qualify. Asked directly with three options (mint anyway / require an
external second source / document only and defer), **Thomas chose mint
anyway**, evergreen — no `releases_per_year`, no `cadence_note` — extending
the one-off-foundational-instrument carve-out (previously used for statutes
and regulations: `br-lc-101-2000`, `eu-reg-2016-2304`) to a document class
that is a *recurring statistical inventory*, not a one-off legal act, on the
strength of Article 9 compelling every member state to keep its inventory
updated even where only one edition has been observed. **G.68 is explicit
that this does not amend §4 itself** — it is a direct ruling on this
21-country batch, and a future session minting a different single-edition
document class needs to ask again, not cite this batch as precedent by
itself.

### `device_bash` is read-only shell, not git, and answers cross-file questions in one call

Introduced G.64, used continuously since. `grep -rl '<node-id>' src/data/research/`
answers "does this already exist?" against the whole repo in one call — two
of G.64's nine punch-list items closed on exactly that command, finding
edges and nodes that had existed in a *different* file since 2026-07-28,
invisible to a file-by-file `_dropped` read by construction. It is shell
access on the user's own mount, not a git operation, and does not touch
`.git` — the git-no-touch rule (`Research.1.md` §2) is about `.git` state,
not about reading files.

### The evidentiary-strength gradient is worth naming explicitly

G.64's Fed/Basel finding is the clearest statement of something that recurs
throughout this window: an instrument's *adoption preamble* naming a
standard is weaker evidence than the standard's own governing document
naming the instrument. OSFI's Chapter 1 says of *itself* that it "is drawn
from" the Basel Framework — asserted inside the standing document. The
Fed's Regulation Q says nothing about Basel in its own codified text; the
naming lives in the 2013 Federal Register notice that adopted it. Both are
real edges. They are not equally strong ones, and the weaker was flagged as
such in its own `basis` field rather than presented at par.

### A citation error in a source document is preserved, not corrected

G.64 finding 5: Montenegro's own national-accounts quality report cites
"Regulation (EU) No 1306/2010" for ESA 2010; the actual instrument is
1306/2013 is CAP financing, not national accounts. Grok's original
transcription — the thing this cheap check set out to verify — turned out
to be accurate; the *source document* is wrong. Kept as a `caveat`, not
closed, not silently fixed: `Research.1.md` §2's quote-as-found rule exists
precisely to preserve this class of finding rather than launder it.

### Screenshot-based verification surviving a compaction needs re-checking, not trusting

G.68's own session was interrupted by a context-window compaction mid-way
through the CIRCABC browser work. The summary handed to the continuing turn
described two mismatches and two render failures in prose, but **could not
preserve the underlying screenshots**, because that verification had only
ever existed as unlabelled images, never transcribed to text. Rather than
proceed on the summary's prose alone, the continuing session recovered the
raw images from the prior turn's own transcript file (JSONL, read directly)
for fourteen countries, and re-verified the remaining seven fresh. **General
practice this establishes: treat a compaction summary describing
visual/screenshot verification as a lead, not a fact, and check whether the
underlying images are still recoverable from the transcript before writing
claims that assume the summary is complete.**

## Mistakes and near-misses worth not repeating

### A sweep can be complete and still miss things a second file sees

G.63's file-by-file `_dropped` read covered `rate-transmission.json` and
`credit-and-mortgages.json` on the same day and recorded both as swept —
without noticing the same CORRA and mortgage-rate nodes already existed in
the second file, built to satisfy exactly the leads the first file was still
recording as open. **This is not a criticism of the method so much as a
demonstration of its one structural blind spot**: file-by-file reading
cannot see across files by construction, the same way a keyword pass cannot
see the "wrongly dropped on too narrow a search" category `Research.1.md`
§4 already names. G.64 closed both as stale in one `device_bash` search.

### A session can catch its own count error before it ships

G.65 delivered a `_status` string reading "Reports 9→10" for the Bank of
Canada lending-rate node, then caught it by directly counting the original
file (10/13, not 9/12) before hand-off, corrected, redelivered, recommitted.
Logged in the file's own Findings rather than smoothed over — not a
predecessor's error to record in Corrections, but exactly the kind of count
error these hand-offs are designed to make embarrassing, and worth keeping
visible for that reason alone.

### "The agency has a page about X" is not "the agency names X as an input"

G.64's Fed/Basel finding, restated as a general trap: the Federal Reserve's
own Basel Regulatory Framework page reads as exactly the kind of citable
source a `_dropped` entry would want, and isn't one — it is an index page
with no citable claim, sitting at a URL that no longer resolves besides.
Worth checking for the same conflation anywhere else a `_dropped` entry
points at "the agency's own page" rather than a specific document or
sentence.

### `_dropped` blockers go stale faster than `_dropped` evidence, and nothing records when a blocker was last tested

G.64's headline, and the transferable claim of the whole window. Six of
nine original punch-list items resolved not because new research was needed
but because the recorded blocker — a site down, a name since changed, a
node another file had already minted — had silently expired and no one had
re-tested the premise. FADN wasn't unreachable; it had been renamed FSDN.
ANZSCO's governance question wasn't unanswered; joint management had ended
in 2024. **A one-line convention — a date stamp on the blocker itself,
distinct from the entry's own date — would let a future sweep sort by
staleness instead of re-reading everything an entry describes as true.**
Not implemented; flagged in G.64 as a schema question for Thomas, still
open at G.68's close.

## Findings about the subject matter

- **The EDP-inventory document class now covers all 26 further CIRCABC
  countries plus Germany — 27 of the ESS's members — at two different
  evidentiary standards.** DE/BE/HR/BG/CY/CZ/EL (7) carry an observed
  interval and a `releases_per_year` figure; the 21 minted at G.68 are
  evergreen by Thomas's direct ruling, single edition, no cadence claimed.
  Both are real nodes; neither should be read as the other's evidentiary
  equal without checking which kind a given country is.
- **Brazil's Lei de Responsabilidade Fiscal names both of its own
  transparency instruments in one article, and the test for which edge type
  applies is whether the statute supplies structure or only a deadline.**
  Art. 48 names the RREO and RGF together; Arts. 52–55 define exactly what
  each report must contain, which is what makes the edge
  `methodology_depends_on` rather than `cites` — the same distinction this
  corpus already drew once, differently, for a Brazilian population-estimate
  edge that gets only a deadline from its own statute.
- **"Quadrimestral" is three times a year, not four, and invites the wrong
  arithmetic on sight.** Brazil's RGF is issued at the close of each
  four-month period — April, August, December — which is three editions,
  confirmed independently via Tesouro Transparente's own descriptive text
  rather than assumed from the word's shape.
- **A definition can identify a document more reliably than its own
  acronym.** Three prior sessions' searches for "IPCN" in EU-side documents
  failed because Eurostat's own methodology annex never uses the acronym —
  it identifies the Luxembourg component only as "the Consumer Prices Index
  (CPI) in the case of Luxembourg" and defines its one distinguishing
  property. Matching that definition against STATEC's own methodology page,
  which does use "IPCN" and states the identical distinguishing property,
  closed a three-session-old negative in two fetches.
- **Joint bi-national governance can end without an obvious announcement
  reaching the document that depends on the fact.** ANZSCO's ABS/Stats NZ
  joint management ended in October 2024 ("the benefits of joint management
  are no longer compelling"), with each country now building its own
  replacement classification. The last *jointly developed* edition still
  described two unilateral revisions before the split was announced —
  drift was visible in the document before the governance question was
  formally answered.
