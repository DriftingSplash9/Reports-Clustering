## Decisions and techniques that now bind

### Grep the corpus for a batch cluster's subject keywords before deep-reading it — proven at scale twice, the single highest-leverage technique in this window

`G.69.md`'s Finding 1 discovered this by accident: an 11-batch cluster chosen
by subject grouping turned out 91% already covered by two untracked prior
efforts, found only after reading all 139 staged records the slow way.
`G.69.md`'s own closing paragraph named the fix — grep first — as the
highest-value next step. `G.70.md` did exactly that, proactively, across
every one of item 5's remaining batches, and it cut the backlog from a
stale "46/47 remain" to a real 16 batches **in one session, having read zero
new staged records** — pure cross-referencing of `01-manifest.json`'s
`scope`/`batch_id` metadata against existing files' own `_status`/`_note`
prose. Two separate untracked passes (a 2026-08-05 "Priority C" effort and a
separate `EU Meta jsons.docx` backlog pass) had built or resolved 18 batches
without ever updating item 5's own tracker — the same class of cross-file
blind spot `[[cheap-check-grep-first]]` already named for individual node
leads, now confirmed to apply at the batch-cluster level too, twice, in
consecutive sessions. **This is now a standing instruction for any future
staging-blob or batch-shaped backlog in this project, not a one-time fix.**

### `npm run validate` runs — from the cloud sandbox, not the device bridge

Every hand-off back to `G.50.md`, and both `R1.68.md`'s and this window's
first three sessions' own Live-problems sections, recorded the same dead
end: the device's own `node_modules` is a Windows install, `esbuild`'s
native binary is `@esbuild/win32-x64`, and it fails outright the moment
`tsx` tries to run it inside the desktop workspace's own Linux VM bridge.
`G.72.md` stopped trying to run it on the device at all: stage `src/**`
(every `.ts`/`.tsx` file, every `.json` in `src/data/research/`) plus
`scripts/validate-data.ts`, `package.json`, `tsconfig.json` into the cloud
sandbox, `npm install` fresh there (a native Linux `esbuild` gets built,
~35s, ~160 packages), then `npx tsx scripts/validate-data.ts`. It ran clean.
**This is now the standing procedure** (also recorded in project memory,
`npm-validate-procedure.md`) for any future session that wants to validate
rather than re-discover the same platform mismatch a sixth time.

### An uncited extraction stub can be trusted for content, and re-fetched to add citation rather than re-derived from scratch

`G.72.md`'s central finding about batch 46 itself: all 26 of the country
peer-review quotes and recommendation counts the staged, uncited stub
carried matched their re-fetched primary sources exactly, sometimes
verbatim. The stub's own `meta.notes` field said it was "consolidated from
all extraction rounds" — and it was accurate, it simply never carried a
`url` through into this particular staging batch. Worth stating generally:
when a staged record fails §6's citability test for want of a `url` but
carries a specific, checkable quote, the fastest correct move is to treat it
as a **citation-recovery task** (confirm the quote is real, find where it
lives) rather than a from-scratch research task (assume the quote might be
wrong and re-derive the claim independently). Both were in fact done this
session — every quote was checked against its source, not merely assumed —
but the search strategy that worked (search for the document, not for the
claim) followed from trusting the stub's content first.

### EU-institutional index pages name without linking — now confirmed three times independently

`G.71.md` found it first (the ESA 2010 Transmission Programme's own table
overview lists table numbers and deadlines, never publication titles).
`G.72.md` found the same shape twice more in one session: Eurostat's own
peer-review index pages (`current-round-2021-2023`, `third-round`) list
every member country by name but link to none of their individual PDF
reports, and Eurostat's own news announcements for Italy and Portugal name
a report as "now online" without linking to it. Three independent
instances, two different EU institutional page types, the same disclosure
asymmetry each time. Worth treating as an established behavior of EU
institutional pages going forward — expect to search for the actual document
host (a member state's own NSI, in Italy's and Cyprus's cases) rather than
trusting an EU index page to link what it names.

## Mistakes and near-misses worth not repeating

### Backlog counts drift silently when more than one untracked effort touches the same source material

`G.70.md`'s central correction: `planning/MISSION-TODO-2.md` item 5's "26 of
73 built, 47 remain" figure was not wrong about the work done under its own
tracking — it was wrong to describe everything else as unbuilt, when two
earlier, separately-tracked efforts (Priority C, the `EU Meta jsons.docx`
pass, both 2026-08-05, both predating item 5's own tracking by two days) had
already resolved most of it. No one did the work wrong; the prose describing
the backlog was never cross-checked against the corpus before being written,
and stayed wrong for five sessions because nothing forced the check. The
grep-first discipline above is the general fix; the specific lesson is
narrower and worth keeping separate: **a backlog tracker's own prose is a
claim like any other, and needs the same "check the corpus, don't just read
the tracker" discipline this project already applies to research leads.**

### A schema defect can sit undetected for three sessions when nothing can run the validator

`G.69.md` set `releases_per_year: null` (rather than omitting the field) on
three new report entries — a straightforward misreading of
`src/lib/types.ts`'s own documentation, which says explicitly that an
evergreen node should omit the field, not null it. This shipped into the
corpus and stayed wrong through `G.70.md` and `G.71.md`, neither of which
touched the same file, and was only caught when `G.72.md` finally got
`npm run validate` running and it failed immediately. **The general risk
this names: every "arithmetic, not a validator run" caveat this chain has
carried since `G.50.md` was not just an unconfirmed number — it was also an
unconfirmed schema**, and a defect could have been compounding silently the
entire time. Now closed for this specific file; the two remaining unrelated
validator errors (see Live problems) show the risk was real elsewhere too,
not hypothetical.

## Findings about the subject matter

- **The corpus's disclosure asymmetry — bound by regulation, the EU names
  no one; coordinating by agreement, it names its sources freely — gained
  its second and third independent corroborations this window** (`G.71`'s
  Transmission Programme, `G.72`'s peer-review index pages), on top of the
  finding's original instances from earlier sessions. Three independent
  primary-source confirmations now support what started as a single
  observation.
- **CPA is the first resolved member of the corpus's biggest documented
  classification gap.** `G.71.md`'s Finding 1: ESA 2010's own Annex A ¶1.22
  names CPA for products, reached the way `Research.1.md` §7's
  classification-hub rule prescribes (read the programme's own prose, not
  the classification's documentation) — the first resolved member of
  `esa2010-quality-reporting.json`'s previously-declined bundled
  "esa-2010 → NACE, CPA, COICOP, COFOG, NUTS" entry. NACE itself stays
  unminted: real and titled at EUR-Lex, but no verbatim Article text was
  retrievable live, twice.
- **Five Eurostat/EU methodology manuals form a coherent
  `methodology_depends_on` cluster, all citing ESA 2010 directly** — the
  Handbook on Quarterly National Accounts, the Manual on Quarterly
  Non-Financial Accounts for General Government, the Manual on Quarterly
  Financial Accounts for General Government, and the Manual on Government
  Deficit and Debt, each stating its own dependency in its own text
  (`G.71.md` Finding 2).
- **The ESS peer-review document class now covers 30 of 32 named members,
  at two different evidentiary depths.** Germany and Slovakia (`G.69`)
  carry full-report-text nodes, found one hop outside their staged batch.
  The 26 minted at `G.72` carry an executive-summary compliance statement
  each, re-fetched from primary sources to replace an uncited staging stub.
  Both are real nodes; neither should be read as the other's evidentiary
  equal without checking which kind a given country is — the same caution
  `R1.68.md` recorded for the CIRCABC EDP-inventory document class's own
  two-tier evidence split.
