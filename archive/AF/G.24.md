## Secondary observations

* **WebFetch can fabricate content for dead URLs rather than reporting the failure.** The Botswana finding (§6) is a new, previously undocumented failure mode for this branch: WebFetch did not merely fail or time out on a 404 URL, it returned a complete, internally consistent, plausible-looking fake report — fake date, fake name spelling, fake figures, fake section reference — with nothing in its output signaling the underlying fetch had failed. The only reason this was caught is that the research agent independently cross-verified with a raw `curl` status check. This is now a standing methodological rule worth stating explicitly for every future round: **before trusting any WebFetch-extracted quote, raw-verify that the source URL actually returns success**, especially for URLs sourced from search-result titles rather than a live, currently-working page.
* **Access failures are frequently more informative once precisely characterized than once merely confirmed.** Several of this round's non-minting findings (Namibia's per-host vs. TLD-wide distinction, Mali's TCP-timeout vs. robots-block distinction, Niger's Interior-not-Mines ministry attribution, Côte d'Ivoire's possible systemic SNDI WAF pattern) turned a previously flat "unreachable" into a specific, actionable, narrower lead. This is worth treating as a standard refinement pass — not just re-trying a dead URL, but characterizing *how* and *why* it fails — whenever an old `_dropped` entry is revisited.
* **A synthesis agent misunderstood the validate/gen distinction on Sudan's file** (§10) — mistakenly believing that running `npm run validate` (which auto-regenerates `slices.generated.ts` via `npm run gen`) would violate the standing rule against *hand-editing* that file. The rule has always meant hand-editing specifically; the auto-generator running as a normal side effect of validate/build is expected and required. This round's corpus-wide validate run confirms no harm was done, but the dispatch instruction to future synthesis agents should state this distinction more explicitly to prevent a repeat.

## How to write the next hand-off

(Copied verbatim per branch convention.)

Required sections, in this order: Orientation, Session conditions, Headline result, Findings (numbered `###` subsections, one per country/topic), Secondary observations, Corrections to prior sessions (never omit this section — even "none this session" is itself a claim, state it explicitly), Thomas's stated priority for the remaining work, Cheap checks still outstanding, What to pass at the start of next thread, and this spec block itself, copied verbatim into every hand-off.

Never edit a predecessor file. Corrections to earlier sessions go in the new file's Corrections section, dated and attributable to this session.

Every claim needs a document behind it — a URL/location and, wherever practical, a verbatim quote. "Comparable with"-type language is not a dependency. Tense matters: a PAST-tense arrangement is not a live dependency; flag it if a source's tense is ambiguous. AGENCY ONLY and NOT FOUND are legitimate research outcomes, not failures — record them in `_dropped` with an honest reason, don't leave the question unanswered and don't force an edge that isn't there.
