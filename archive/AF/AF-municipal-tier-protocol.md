# AF branch — municipal-tier research protocol

A reusable brief for dispatching municipal-tier (city/commune/LGA-level) research in the Economic Report Influence Graph's Africa branch. Written 2026-08-13 after AF/G.18's first 10 rounds, to speed up rounds 11-20 and any later municipal-tier work without re-deriving the approach each time. Pair this with a fresh read of the most recent `AF/G.*.md` hand-off for current corpus state before dispatching anything.

## The standing evidence rule (do not relax this)

Every claimed fact or dependency needs a verbatim quote and an exact URL from a PRIMARY document — government- or agency-authored, not a news article, NGO paraphrase, blog, or Wikipedia. "NOT FOUND" is a completely legitimate, valuable outcome; record it honestly in `_dropped` with a specific reason, don't leave it unminted and unmentioned. Never paraphrase a secondary source into sounding like a primary one. AI-summarized-only sourcing (where a fetch tool could only retrieve a rendered summary, not raw HTML/PDF text) is acceptable but must be flagged distinctly in the node's own description, not presented as equivalently verified.

## Sequencing: population-descending, with a structural fallback

Work down Africa's population ranking (re-verify current figures with a fresh search each time you start a new phase — don't trust a remembered ranking, it drifts and the exact ordering in the middle of the list is easy to get wrong). Before dispatching a country, check the existing corpus for that country's current municipal-tier (`jurisdiction_level: "municipal"`) coverage — skip or deprioritize countries that already have solid municipal nodes (as of 2026-08-13: South Africa, Kenya, Uganda, Ghana, Morocco all have real municipal-tier documents already) in favor of genuinely uncovered countries, even if the covered ones rank higher in population.

Thomas's own framing, worth repeating to every dispatched agent: expect a "collapse of structure" from strong municipal fiscal documentation at the top of the population ranking toward thin-or-absent documentation at the bottom — but AF/G.18 found this tracks each country's actual institutional design more than population rank alone (Tanzania and Algeria, ranked 5th and 10th, produced richer finds than Egypt and Ethiopia at 2nd and 3rd, because Egypt and Ethiopia's real sub-national architecture genuinely has no ordinary elected-municipal tier). Don't force the population-cliff narrative if the evidence doesn't support it for a given country — a structural absence (confirmed, not assumed) is itself a valid, valuable finding.

**The fallback rule**: when a country's municipal tier proves thin or genuinely nonexistent (after real search effort, not a quick guess), redirect that country's remaining research budget to re-scour the PROVINCIAL/STATE tier specifically for missed NATIONAL-level connections (regional bloc citations, methodology-manual naming, cross-institutional dependencies) rather than forcing a nonexistent municipal finding. This is not a consolation prize — some of AF/G.18's best finds (Sudan's national-tier deepening, DRC's second distinct 40%-cascade rule one tier below the existing provincial finding) came from applying this fallback deliberately rather than reluctantly.

## The per-country dispatch template

Structure each Agent-tool dispatch as a self-contained brief (the agent has no memory of this conversation) covering:

1. **What the existing corpus already has for this country** — list the specific node IDs and what they cover, so the agent doesn't redo prior work. Pull this from a quick corpus grep before writing the brief, not from memory.
2. **2-4 concrete search angles**, informed by what's already missing or what a genuinely comparable country's structure suggests might exist (e.g. "does a chartered/federally-administered capital city exist, structurally parallel to Addis Ababa/Dire Dawa?" or "does an equalisation/compensation fund with a named percentage exist, structurally parallel to Mozambique's FCA or Angola's FEAL?").
3. **The document-type checklist** (each of these has produced real finds in this branch — check all of them, not just the obvious "does the city have its own website" angle):
   - The city/commune's own government website or finance-bureau page
   - The national organic/enabling law establishing municipal government (citable even without an implementing budget document — see Liberia's LGA 2018 and Angola's Lei 15/17 precedents)
   - The national MUNICIPAL FINANCE law specifically (distinct from the organic/institutional law) — this is usually where actual transfer formulas/percentages live (see Mozambique's Lei 1/2008, Angola's Lei 13/20, Tanzania's Local Government Finance Act CAP. 290)
   - **A higher tier of government REPORTING ON named lower-tier units** — this is a distinct, often-overlooked document type that produced some of AF/G.18's richest finds: a STATE Auditor-General's report naming individual LGAs (Nigeria), a national ministry publishing per-LGA budget files (Nigeria/Kano), a federal budget proclamation itemizing named cities (Ethiopia). Search explicitly for this pattern, not just for lower-tier self-publication.
   - The annual national Finance Law / Budget Law's own annexes — sometimes the real percentage-and-figure detail lives here, not in any enabling law (see Algeria's État E finding, the richest of the round).
   - The national statistics agency's own CPI methodology page, checked for COICOP, the IMF/ILO CPI Manual, and regional-bloc naming (AFRISTAT, COMESA, SADC HCPI, EAC, the African Charter on Statistics) — a standing secondary objective in every dispatch, not just the primary municipal-fiscal question.
4. **Explicit fallback instruction**, worded so the agent doesn't need to ask: "if genuinely nothing found at [X] level after real search effort, pivot to [specific named alternative angle]."
5. **The output format**, restated in every brief:
   ```
   URL: [exact URL]
   LOCATION: [page/section/article]
   QUOTE: [verbatim quote]
   NAMES: [agency/document] or AGENCY ONLY
   TENSE: PRESENT or PAST
   NOTES: [caveats]
   ```
   Explicitly instruct the agent to report EVERY URL checked, including negative/failed ones, with the specific access-failure mode (TLS/certificate error, Cloudflare gate, robots.txt block, network-level 502, JS-rendered SPA with no extractable text) — this branch treats "confirmed content absence" and "technical access failure" as meaningfully different outcomes, and conflating them loses information a future round could act on (retry with different tooling, vs. treat as settled).

## Synthesizing agent findings into corpus files

- **Check for existing node conflicts before minting.** Read every existing file for the target country in full (not just node IDs) before writing new JSON — AF/G.18 found several cases where a "new" finding was actually enriching an EXISTING node's description (Tanzania's Zanzibar OCGS page, Egypt's Local Administration Law, Madagascar's organic law) rather than warranting a new node. When enriching, prepend an `UPDATE [date] (AF/G.[n], [round description])` marker to the existing description rather than replacing it wholesale, so the paper trail of what was known when stays intact.
- **Watch for genuinely distinct laws with similar names/numbers** — Angola's Lei 15/16 (deconcentrated administration, already in corpus) and Lei 15/17 (decentralized autarquias, new this round) are different instruments; don't assume a similar node ID or law number means duplication without reading both.
- **`_dropped` reason-field discipline (runtime-guard rule, do not violate)**: `reason: 'resolved'` or `'caveat'` REQUIRE the named edge to ACTUALLY EXIST as a live dependency in the graph — if you're documenting that a document was found but no edge is actually being drawn (e.g., a Constitution has no reason to cite a CPI report), use `reason: 'note'` instead. This has been the single most common near-miss error in this branch across multiple sessions — double-check every `resolved`/`caveat` note against the actual `dependencies` array before shipping.
- **Domain values** are a closed enum (`src/lib/types.ts`, `Domain` type) — never invent a new one; check the list before assigning. As of 2026-08-13: inflation, labour, monetary-policy, national-accounts, benefits, interest-rates, municipal-finance, education, post-secondary, health, fiscal-transfers, population, taxation, assessment, energy-royalties, banking, financial-regulation, construction, insurance, research-innovation, agriculture, external-action.
- **Country-family palette check**: any new country code needs an entry in `COUNTRY_FAMILY` (`src/lib/palette.ts`) or validation fails — but municipal-tier work on already-covered countries (which is most of it, since a country needs SOME prior national-tier presence before it's worth municipal-tier dispatch) typically needs no palette changes. Check anyway before shipping.
- **`releases_per_year`**: omit entirely (don't set to null) for one-off instruments (laws, constitutions, single reports) — only set it for genuinely recurring publications.
- **`relationship_type` discipline**: `calculated_from` for a document that explicitly computes ITS OWN figures FROM another named document/formula; `methodology_depends_on` for a direct "our methodology IS X" claim; `uses_data_from` for a compiling/aggregating relationship (e.g. a regional bulletin aggregating national data); `cites` for general support/institutional-acknowledgment mentions or where a document names another without a specific formula-level dependency. Don't default to `cites` for everything — this round found several genuine `calculated_from` relationships (Madagascar's FNP report computing its own funding percentages from the resources law's own article numbers) that would have undersold the finding if flattened to `cites`.

## Validation and shipping

Standard pipeline (see project memory `npm-validate-procedure` for full mechanics): tar the relevant files from the device into the cloud sandbox, `npm install` if needed, run `npm run validate` and `npm run build`, fix anything that fails, then `SendUserFile` + `device_commit_files` (with `force: true`) to push corrected files back to the device. Expect the 2 known pre-existing Rwanda/Uganda `_dropped`-note validator warnings (`rw-nisr-cpi -> eac-hcpi-regulations` and `ug-ubos-cpi -> eac-hcpi-regulations`, both `reason: 'no-document'` describing an edge that already exists) — these are out of scope for municipal-tier work and pre-date it; don't spend time on them unless specifically asked to.

## Hand-off and Grok follow-up cadence

Every ~10 rounds (or whatever cadence Thomas specifies for a given push): write a hand-off (`AF/G.[next-number].md`, following the exact section order and spec block at the bottom of the most recent hand-off — never edit a predecessor file) and a Grok follow-up prompt covering that round's genuine open items (delivered via `SendUserFile` only, per this branch's standing convention that Grok prompts are not committed to the repo). Prioritize for the Grok prompt: (a) technical access failures where a differently-configured fetch might succeed where this session's didn't, (b) genuine NOT FOUNDs worth a second, independent search angle, (c) any status question that could have changed recently (election dates, membership status, law-passage status) — flag these explicitly as "please note if this has changed." When processing Grok's response in a later session: always independently re-verify any paraphrased/translated quote against the actual primary text before minting — this branch has caught real Grok paraphrase errors twice already (a Nigeria VAT formula, a Djibouti Constitution mistranslation), so treat Grok's findings as strong LEADS, not as sourced quotes in themselves, until independently checked.
