# Audit — Economic Report Influence Graph

Independent technical and evidentiary audit per the brief of 31 August 2026.
Tree audited: `main` @ `fd18b55` (GitHub == local working tree, clean at time of audit).
The repo has moved past the brief's 2026-08-30 snapshot (~3,430 / ~3,317 / ~700): the 2026-08-31 audit-response rulings (D1/D4/D7) landed first. Live counts used throughout: **3,354 reports · 2,815 dependencies · 963 isolates**. Drift noted per brief §14; audited the live tree.

## 9.1 Verdict

The evidence rule is real, now enforced in code, and holds where the corpus is mature: every sampled statute, regulation and methodology annex that could be fetched supported its edge, the loader can no longer silently lose an evidenced edge (superseded duplicates fail the build), commercial and terminus exclusion are behaviourally asserted on every validate run, and the remaining evidence debt (162 no-URL + 5 bare-homepage edges) is exactly counted, quarantined as warnings, and queued. But the audit found one confirmed systematic violation at the very top of the ranking: 19 of the 31 edges that make the BRICS Joint Statistical Publication the **#3 authority node** (0.411) cite one publications-index page that names no data source — the sampled instance fails, and the validator's bare-homepage check cannot see it because the URL carries a path. The two Rosstat regional series at **#8 and #9** rest on consistency-assertion bases whose rosstat.gov.ru citations cannot be machine-verified from this environment, so their evidentiary status is suspected-weak, unproven either way. Sampled fail rate is 11.6% (5/43 scored; 5.0% excluding the already-flagged no-URL class), weak-or-fail 30.2% — sitting on the brief's ~30% line, with the weakness concentrated in the newest BRICS-import strata and in a recurring "names the agency, not the artefact" citation shape that needs a ruling rather than research. The graph is safe to read as an evidence-backed influence map on its hand-researched branches; the top of its authority ranking is not currently trustworthy above rank ~5 until the BRICS-JSP and Rosstat evidence classes are re-cited or demoted, and a *targeted* evidence pass (not corpus-wide) is warranted.

**Overall: HOLD WITH CAVEATS**

## 9.2 Method

**Read** (in brief §4 order): the brief; START-HERE.md; HANDOFF.md (2026-08-31); REPORTS.md; PLAYBOOK.md; README.md; then `src/data/index.ts`, `assembleCorpus.ts`, `types.ts`, `graph.ts`, `filter.ts`, `selection.ts`, `ViewControls.tsx`, the camera-fit and force wiring in `InfluenceGraph.tsx`, `scripts/validate-data.ts`, `gen-slices.ts`, `measure-forces.ts`, and the sampled research slices.

**Ran** (cloud Linux sandbox, Node 22, fresh `npm install` on a GitHub clone of `fd18b55` — the local tree was confirmed identical and level with origin/main before cloning; no git was run in the working folder after reading the standing rule, and a check confirmed no `index.lock` was left by the one `git status` run before that rule was read): `npm run validate` (exit 0; 123/123 logic checks), `npm run check` (clean), `npm run build` (clean), a read-only dump script (`scripts/audit-dump.ts`, created in the cloud clone only — not in the user's tree), `scripts/measure-forces.ts` with `SEEDS=1,2 CRS=0,15`, and a Playwright/Chromium software-render session against `npm run dev` (SwiftShader; **no GPU — no FPS numbers claimed anywhere in this report**).

**Sample sizes** (fixed seed 20260831, strata per brief §7.2): S1 top-10 authority nodes × ≤2 incident edges = 20; S2 top-5 high-degree non-authority nodes × 2 = 10; S3 recently minted BR/IN/CA/AE/ID edges from the 2026-08-30 round slices = 13 (three slices had <3 live edges); S5 commercial-incident = 5 of the 7 existing; S6 random remainder = 20. **Total 68 edges**, plus 15 isolates classified. Corpus snapshot: `public/corpus-data.json` as generated by this validate run, 2026-08-31.

**Decision rule** (written before scoring; verbatim copy retained):
- **pass** — the cited document states the relationship in words, naming the target specifically (title, series id, or an unambiguous equivalent — including a figure/chart source caption per PLAYBOOK §7, a statute/regulation prescribing the input, or the target-side document in reverse voice, "the data are used by").
- **weak** — a related document names only the agency/class, not the artefact; or a source list/index names both without stating use; or the passage supports a weaker relation than the edge's `relationship_type`.
- **fail** — no justifying passage; wrong class of page (homepage, portal/topic shell, index); wrong document; contradiction; or no `evidence_url` at all.
- **unverified** — well-formed, right-class URL unreachable from this network (robots/policy refusal, TLS failure, 404 with no reachable archive, or PDF interior beyond fetch truncation). Excluded from the fail/weak denominators, reported separately (brief §12).

Verification was run by seven parallel checking agents on WebFetch only (no curl/scripting fetches), Wayback allowed only for network-type failures and only when the snapshot is the cited document. Four verdicts were adjudicated by me after the fact, each marked `*` in the ledger with the original verdict recorded: one pair-harmonisation (idx 29, same URL as a pass; I re-fetched the page myself) and three re-applications of the pre-written truncation clause to BPS publication-landing-page citations (idx 39/42/49 → unverified), where the project's own convention (PLAYBOOK: "always cite the stable page, never the signed link") puts the quoted footnote inside a PDF the fetch tool cannot reach. Pre-adjudication rates for transparency: fail 15.2%, weak-or-fail 37.0% of 46 scored.

**Hardware:** none (cloud container, software rendering only). **Network:** materially constrained — 25/68 edges (37%) unverifiable, dominated by rosstat.gov.ru TLS failures, s-circabc.europa.eu 404s, kings-printer.alberta.ca robots refusals, and a proxy that blocks web.archive.org playback. This is the audit's biggest limitation and is reflected in §9.6.

## 9.3 Findings

**F-01 · Severity: high · Area: data · Status: confirmed**
The #3 authority node's incoming evidence is systematically index-shaped. 19 of 31 edges into `brics-jsp` (authority 0.411) cite the same publications-index page, `https://brics.ibge.gov.br/publicacao.html`. The sampled instance (`br-epe-balanco-energetico-nacional -> brics-jsp`, idx 05) **fails**: the page lists JSP editions and chapter names, and never mentions BEN, EPE, or any national data source. The 6 edges citing the JSP-2024 PDF on rosstat.gov.ru are unverifiable from this network (idx 04). Node size at the top of the ranking is currently carried by citations that do not state the relationship.
*Evidence:* `/tmp/ledger-final.json` idx 04–05; URL count from `public/corpus-data.json` (19× publicacao.html).
*Reproduction:* fetch the page; grep for "EPE"/"Balanço"/"source" — nothing.
*Recommended fix:* re-cite the 19 edges against the JSP PDF's own source statements (or each NSO's contribution statement) or move them to `_dropped` per ruling 1-A; the node's rank should not survive as-is.

**F-02 · Severity: medium · Area: validation · Status: confirmed**
The bare-homepage check only catches root URLs. `isBareHost` (graph.ts) flags `https://host/` but passes any path — so `…/publicacao.html` (19 edges, F-01), `rosstat.gov.ru/folder/64494`, and `inegi.org.mx/temas/turismo/` (idx 48, **fail**, topic shell) all clear the EVIDENCE block silently. The 5-edge bare-homepage count materially understates the pointer-not-source class.
*Evidence:* graph.ts `isBareHost` (~line 102); ledger idx 05, 14, 17, 48.
*Reproduction:* inspection + the three sampled fails/suspects.
*Recommended fix:* extend the warning to known index/topic/folder path shapes (`/publicacao`, `/temas/`, `/folder/`, `/statistics$`) or to any URL cited by ≥N edges (the 19× reuse is itself the tell).

**F-03 · Severity: high · Area: data · Status: suspected (reproduction path stated)**
The Rosstat regional cluster (#8 `ru-rosstat-regions-russia-socio-economic` 0.255, #9 `ru-rosstat-grp-series` 0.248 — 2 of the top 9 authority slots) rests on assertion-shaped bases: sampled bases read "data … are consistent with …" / "presents VRP figures consistent with the national series" (idx 14, 17), which state consistency, not documented use; idx 15 (**weak**) cites a Rosstat page that never names the claimed 282-FZ target; idx 16 unverifiable. 117 corpus edges cite rosstat.gov.ru, which fails TLS from this environment and whose Wayback snapshots the fetch proxy rejects, so the cluster could not be scored either way.
*Evidence:* ledger idx 14–17; 117-edge count; authority table.
*Reproduction:* open the four cited rosstat.gov.ru pages in a real browser and check whether any names the dependent publication.
*Recommended fix:* a browser-session re-citation round for the RU regional slices, treating "consistent with" bases as leads, not evidence.
