# V0.1 — Data model, seed set, and first render

Session date: 2026-07-27
Covers roadmap milestones **0** and **1**.

---

## What was built

**Project scaffold.** Vite + React 19 + TypeScript, with React Three Fiber and
`three-forcegraph` doing the 3D work. No backend, no database — the seed data is
TypeScript modules compiled into the bundle. That is deliberate at this size:
18 reports do not need infrastructure, and keeping the data as typed source
means a bad edit fails at compile time instead of at runtime.

**Data model** (`src/lib/types.ts`). Two entities, `Report` and `Dependency`,
following REPORTS.md. Three additions to the spec, each for a reason:

- `releases_per_year: number` — the coarse enum could not express real cadences.
  See "Friction with the spec" below.
- `basis: string` on every edge — a sentence saying why the dependency is
  believed to exist. Without it a curated graph quietly becomes a graph of
  plausible-sounding guesses.
- `country: 'CA' | 'US'` — recorded but not yet used visually.

**Seed set** (`src/data/`). 18 real releases, 27 dependencies. Statistics
Canada, Bank of Canada, ESDC/CRA, BLS, BEA, Federal Reserve, SSA. Every node is
connected; nothing was added as filler. Chains that actually resolve:

- CPI → OAS quarterly indexation → (statutory formula)
- SEPH average weekly earnings → YMPE → CPP disability benefit amount
- BLS CPI → PCE price index → NIPA GDP → FOMC statement → H.15
- BLS CPI → Social Security COLA

**Scoring** (`src/lib/graph.ts`). Weighted PageRank over the dependency graph,
with edge weights by relationship type (`calculated_from` 1.0, `uses_data_from`
0.8, `methodology_depends_on` 0.5, `cites` 0.25). Edge direction already points
from dependant to dependency, so rank flows toward foundational reports without
needing to reverse anything. Raw in-degree is computed alongside it as a check.
Node radius is `sqrt(authority)` — the eye compares area, so linear scaling made
the top node swamp the scene.

**Renderer** (`src/components/InfluenceGraph.tsx`). Dark scene, spheres coloured
by primary domain, emissive intensity rising with authority, directed arrows on
edges, canvas-sprite labels, orbit controls. Link distance varies with edge
weight so strong dependencies sit closer — clustering emerges from the data
rather than being imposed.

**Minimal HUD** (`src/App.tsx`). Static overlay: counts, top three by authority,
domain legend. This is *not* the milestone 4 detail panel. It exists only
because milestone 1 asks for legibility and unlabelled colours are not legible.

## Does the premise hold?

This was the real question for milestone 0, and the answer is yes. Both scoring
methods independently put the two CPIs at the top:

| | Weighted authority | Raw in-degree |
|---|---|---|
| 1 | BLS Consumer Price Index — 1.00 | BLS Consumer Price Index — 5 |
| 2 | StatCan Consumer Price Index — 0.67 | StatCan Consumer Price Index — 4 |
| 3 | BEA Personal Income and Outlays — 0.57 | BEA Personal Income and Outlays — 3 |

Consumer price measurement comes out as the foundation of both national systems
without anything being tuned to produce that result. The bottom of the ranking
is equally correct: SSA COLA and CPP disability amounts are pure derived
outputs that nothing else consumes.

## What is broken or unverified

**The render has not been seen.** It type-checks and the production build
succeeds, but no one has looked at it. The sandbox this was built in has no GPU
and no browser libraries, so a headless screenshot was not possible. **First
thing to do is run `npm run dev` and look.** Expected failure modes, in order of
likelihood: labels colliding into unreadable soup; the scene framed wrong so
everything is off-camera; arrows too small to read at default zoom.

**A stale `node_modules` folder is sitting in the project directory.** An
install was started from a Linux sandbox, failed partway, and the files could
not be deleted through that mount. It is a partial install for the wrong
platform. Delete the folder in File Explorer before running `npm install`.

**SEPH ranks higher than it should.** The Survey of Employment, Payrolls and
Hours sits 4th on weighted authority but 9th on raw in-degree — the largest
disagreement between the two methods, and `npm run validate` flags it. The cause
is not bad data. It is that SEPH sits at the end of a three-node chain
(disability amount → YMPE → SEPH) where every link is `calculated_from` and each
node has exactly one outgoing edge, so the full weight of the chain concentrates
on it. PageRank is behaving correctly; whether the *result* is right is a
judgement call. Three ways to respond, in increasing order of effort:

1. Accept it. An exclusive statutory dependency arguably *is* strong.
2. Add the missing edges. SEPH is genuinely used more widely than one link
   suggests; the graph is thin here rather than the maths being wrong.
3. Damp long chains by reducing the damping factor in `pagerank()`.

Option 2 is probably correct and mostly resolves itself at milestone 5.

**`last_updated` is null everywhere.** Not wired to any source. Left null rather
than filled with invented dates, which would silently corrupt the cadence
simulation at milestone 3.

**Cross-border linkage is thin** — two edges, both from the Bank of Canada's
Monetary Policy Report, both `cites`. This is honest rather than incomplete: the
two statistical systems genuinely do not consume each other's outputs as
computational inputs. Expect the Canadian and US clusters to sit apart. If that
reads as broken rather than as a finding, it is a visual problem to solve at
milestone 7, not a reason to invent edges.

## Friction with the spec

REPORTS.md fixes `update_frequency` to five buckets. Two important releases do
not fit: the Bank of Canada policy rate and the FOMC statement both come out
**eight times a year**, roughly every six weeks. Neither "monthly" nor
"quarterly" is true.

Rather than write something false into the data, both fields now exist:
`update_frequency` stays as the coarse enum for filtering, and
`releases_per_year` carries the real number for the cadence simulation. The
affected records also have a `cadence_note` explaining the gap.

**This needs a decision before milestone 3**, since the pulse timing depends on
it. The options are to keep the split as-is, extend the enum, or drop the enum
and derive buckets from `releases_per_year`.

## Recommended next steps

1. **Run it and look at it.** Everything below is guesswork until then.
2. **Milestone 2 — directed influence.** Click a node, highlight its dependants
   upstream and its dependencies downstream, dim everything else. This is the
   feature that makes the graph answer questions rather than just look like
   something.
3. **Decide the cadence question** above.
4. **Then milestone 5** — grow to 30–80 reports. The scoring and layout are
   more informative with more nodes, and it fixes the SEPH artefact naturally.

Milestone 3 (the ripple pulse) is tempting to do next because it is the most
visually striking, but it needs `last_updated` wired to something real and the
cadence question settled first. Doing it now means building on two placeholders.
