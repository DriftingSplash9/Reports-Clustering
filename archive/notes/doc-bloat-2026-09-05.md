**2026-09-05.** Thomas asked whether the documents `HANDOFF.md` §1 tells an
agent to read have grown bloated. They have. He approved all five trims below
and ruled they happen **after** the next agent has made progress on the §3 todo

executed; the docs are exactly as they were when it was written.

The problem is not length alone. Four things are **duplicated**, and one large
block is **stale in a way that contradicts `HANDOFF.md`**.

### Duplication

1. **Two routing tables that disagree** — `HANDOFF.md` §1 and `PLAYBOOK.md` §1
   both route the agent by task. PLAYBOOK §1 also opens "`HANDOFF.md`, then this
   file. Both are short by design."
2. **Two do-not-re-raise ledgers** — `PLAYBOOK.md` §7 (14.7 KB) and
   `REPORTS.md` "Decisions (previously open questions)" (**43.8 KB, 58% of
   REPORTS**). The REPORTS one is design archaeology from the 33-to-121-node
   era: palette choice, the domain-filter removal, authority retention, mutual
   pairs, `part_of`. None of it is needed before corpus work.
3. **Three copies of the standing rules and the sandbox recipe** — PLAYBOOK §2,
   `notes/techniques-2026-09-04.md` §1, and both `next-agent-prompt-*` files.
4. **Round narratives in two places** — 16 `notes/` files (~140 KB) whose
   stories project memory already carries, against §4's own rule that a
   finished round's story goes to memory.

### Staleness that actively misleads

`REPORTS.md`'s tail — "Legibility at scale — what 121 nodes actually looks
like" and "Still genuinely open" — is written against a **121-node** graph and
asserts *"the graph is one component with no orphans under the strict
standard."* `HANDOFF.md` §2 currently shelves **four ISOLATED nodes**. Both are
in the mandated reading.

## The five trims — all approved, do them in this order

1. **Cut `REPORTS.md` "Decisions (previously open questions)" to a one-line
   index.** One line per decision, each naming where the narrative went; move
   the prose to `archive/decisions/` (the folder already exists). This single
   move takes the mandated read from ~220 KB to ~180 KB.
2. **Delete `REPORTS.md` "Legibility at scale" and "Still genuinely open".**
   Both are superseded by `HANDOFF.md` §2/§3 and one of them is now false.
   Anything still live in them moves into the HANDOFF todo *first*, in the same
   edit — do not lose an open question to a cleanup.
3. **Delete `PLAYBOOK.md` §1's table**, replaced by one line: routing lives in
   `HANDOFF.md` §1. Fix the two dead pointers and remove the grok-diary
   mandate from §5 (or write the diary — Thomas's call, and it is a separate
   question from this cleanup).
4. **Retire `notes/next-agent-prompt-2026-09-03.md`** (superseded by the
   -09-04 file) and cut the -09-04 Standing block to "read `HANDOFF.md` §1 and
   follow its table" instead of restating the rules a third time.
5. **Move the 16 orphan notes to `_to_delete/`** (rule 6 — agents cannot
   delete), one line each in `_to_delete/README.md` naming the project-memory
   entry that supersedes it. **Check the memory entry exists before moving the
   file**; if a note has no memory entry, write the entry first or leave the
   note where it is.

## Rules this cleanup must not break

- **Rule 6.** Nothing is deleted from disk — `_to_delete/`, logged. "Delete" in
  items 2, 3 and 4 means *remove those sections from the living document*; the
  superseded prose still lands in `archive/` or `_to_delete/`.
- **`START-HERE.md` is product copy** — it renders in-app as Help ▸ What this
  is. It is NOT in this cleanup. Its known defect (F-07, the ranking sentence,
  now wrong in a new way) stays where it is, in §3 item 9.
- **Archive before you overwrite.** No git safety net. Copy the pre-cleanup
  `REPORTS.md` and `PLAYBOOK.md` into `archive/` before editing either.
- **Measure it afterwards.** Re-run the byte count of the §1 reading list and
  put the new number in the handoff, so the next review has a baseline rather
  than an impression.
